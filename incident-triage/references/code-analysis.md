# Контур кода: от ошибки к месту в проекте

`scripts/code_hints.py` собирает материал, выводы делаешь ты. Скрипт не правит код и
не угадывает причину — он показывает, куда смотреть.

## Что делает скрипт

```bash
python3 scripts/code_hints.py --from-parsed /tmp/parsed.json --repo .
python3 scripts/code_hints.py --log stacktrace.txt --repo ../backend
python3 scripts/code_hints.py --text "NullPointerException at com.acme.Pay.charge(Pay.java:88)"
cat trace.txt | python3 scripts/code_hints.py --repo .
```

1. **Фреймы стектрейсов** — Java/Kotlin, Python, JS/TS, Go, C#, PHP, Ruby. Ищет файл
   в проекте по имени, печатает строку с контекстом ±3 и `git blame` этой строки.
2. **Текст ошибки** — берёт из шаблона куски без плейсхолдеров и грепает по проекту:
   находит место, где сообщение порождается. Работает там, где стектрейса нет вообще.
3. **Классы исключений** — свои они или библиотечные.
4. **Коммиты за сутки до первой ошибки** — из `git log` по окну инцидента.

## Как читать результат

**Верхний свой фрейм важнее.** В стектрейсе первые фреймы обычно из библиотек.
Ближайший к верху фрейм, который нашёлся в проекте, — место, где ошибка стала
неизбежна. Именно его читай первым.

**Файл не найден в проекте** — это ответ, а не пустой результат. Значит падает
внешняя библиотека или соседний сервис, и чинить, вероятно, надо не здесь.

**Текст ошибки не нашёлся грепом** — сообщение приходит извне: драйвер БД, прокси,
балансировщик, ядро. Часто важнее самого исключения.

**Коммитов в окне нет** — свежий код ни при чём. Смотри конфиг, данные, нагрузку,
соседние сервисы, инфраструктуру. Это сильный сигнал, его легко упустить.

**Коммиты есть** — не хватайся за первый. Проверь, трогает ли он найденные файлы:
корреляция по времени сама по себе ничего не доказывает.

## Типовые связки «симптом → что смотреть»

| Симптом в логах | Где искать в коде |
|---|---|
| `connection pool exhausted`, рост latency | размер пула, таймауты, незакрытые соединения, транзакции без commit |
| `NullPointerException` / `AttributeError: NoneType` | необработанный пустой ответ, отсутствующее поле в payload, изменение контракта API |
| `timeout` при вызове соседнего сервиса | клиентский таймаут vs серверный, ретраи без backoff, отсутствие circuit breaker |
| OOM, `Killed`, обрыв лога без ошибки | лимиты контейнера, чтение файла/выборки целиком в память, утечка в кеше |
| 502/504 от прокси | приложение не отвечает или дольше таймаута прокси — смотри логи *приложения*, не прокси |
| Ошибка сериализации/десериализации | рассинхрон версий контракта между сервисами, новое обязательное поле |
| `deadlock`, `lock wait timeout` | порядок захвата блокировок, длинные транзакции, миграция под нагрузкой |
| Работает на одном стенде, падает на другом | конфиг и переменные окружения, версии зависимостей, данные, а не код |

## Правила предложений по коду

- **Сначала причина, потом патч.** Фикс до подтверждённого механизма — это угадывание.
- **Минимальное изменение**, устраняющее причину. Не переписывай модуль заодно.
- **Показывай diff и объясняй**, что именно он меняет в поведении. Не применяй молча.
- **Проверь, что не сломает соседей**: тот же пул/таймаут/лимит может использоваться
  в других местах.
- **Скажи, как проверить фикс** — какой лог или метрика подтвердит, что помогло.
- **Обходной путь и постоянный фикс — разные вещи.** Помечай их явно, оба записывай
  в базу знаний.
- Если причина в конфиге, данных или инфраструктуре — так и скажи. Правка кода
  ради маскировки симптома хуже, чем отсутствие правки.

## Обратная связь в базу знаний

Разобрался — сохрани точку входа, чтобы в следующий раз не искать заново:

```bash
python3 scripts/kb_add.py --title "..." --file src/db/pool.py --commit a1b2c3d \
  --from-parsed /tmp/parsed.json ...
```

`kb_search.py` покажет эти файлы в результатах — второй раз тот же баг сразу
указывает на место в коде.
