# Постмортем: <краткое название инцидента>

**Дата инцидента:** YYYY-MM-DD
**Стенд:** prod / stage / …
**Длительность:** от первой ошибки до восстановления
**Влияние:** кого и как задело (пользователи, заказы, деньги, SLA)
**Статус:** черновик / согласован
**Связанная запись базы знаний:** INC-YYYY-MM-NNN

Разбор безоценочный: анализируем систему и процесс, а не людей. Имена — только в
контексте действий («дежурный откатил релиз»), без оценок и поиска виноватых.

## Краткое изложение

Три-четыре предложения: что сломалось, почему, как починили. Читается отдельно
от остального документа.

## Хронология

Из `timeline.py`. Каждая строка — время, событие, источник. Только факты.

| Время | Событие | Источник |
|---|---|---|
| 12:20 | Деплой payment-api 1.24 | CI |
| 12:31 | Первые `connection pool exhausted` | app.log |
| 12:34 | Всплеск 88 ошибок/мин | app.log |
| 12:41 | Алерт, дежурный подключился | мониторинг |
| 12:58 | Откат на 1.23, ошибки прекратились | CI |

Отдельно отметь:
- **время начала** (первая ошибка, а не первая жалоба);
- **время обнаружения** — разрыв с началом показывает дыру в мониторинге;
- **время восстановления**.

## Причина

Механика отказа, а не название ошибки. Что именно и в какой последовательности
привело к отказу.

### Пять «почему»

1. Почему пользователи получали 504? — Запросы висели дольше таймаута прокси.
2. Почему висели? — Ждали свободное соединение к БД.
3. Почему ждали? — Пул исчерпан: 20 соединений при 60 rps.
4. Почему не хватило? — Релиз добавил синхронный запрос в горячий путь.
5. Почему не поймали заранее? — Нагрузочного теста на этот путь нет.

Останавливайся там, где дальше начинается «человек ошибся» — это не причина, а
место, где система не подстраховала.

## Что сработало / что нет

**Сработало:** что помогло быстро найти и починить.
**Не сработало:** чего не хватило — алерта, логов, дашборда, документации, доступа.
**Повезло:** что могло сделать хуже, но не сделало. Отдельный пункт — эти места
чинят до следующего раза.

## Действия

| Действие | Тип | Владелец | Срок | Тикет |
|---|---|---|---|---|
| Поднять pool_size до 50 | устранение | | | |
| Алерт на утилизацию пула > 80% | обнаружение | | | |
| Нагрузочный тест на путь оплаты | предотвращение | | | |

Три типа: **устранение** (чтобы не повторилось), **обнаружение** (чтобы заметить
раньше), **предотвращение** (чтобы не внесли снова). Каждое действие — с владельцем
и сроком, иначе это пожелание, а не действие.
