# Сбор карточки инцидента вопросами

Начало разбора — самое дорогое место для пользователя: он уже написал, что сломалось, а
скилл просит дописать стенд, время и способ передачи логов. Часть этого — закрытые
списки, и спрашивать их текстом незачем.

Правило: **вариантами спрашивается то, откуда варианты берутся; остальное — свободным
вводом.** Инструмент — встроенный инструмент вопроса с вариантами; его имя на каждой
платформе см. в `platforms.md`.

## 1. Что чем спрашивается

| Вариантами | Свободным вводом |
|---|---|
| стенд (dev/test/stage/prod) | симптом словами пользователя |
| сервис, когда его видно из репозитория или базы знаний | шаги воспроизведения |
| окно времени (последний час / сегодня / конкретное) | путь к файлу или архиву логов |
| способ передачи логов | ссылка на выборку в Kibana/Grafana/Sentry |
| выбор между несколькими найденными источниками логов | вставка фрагмента лога |
| тип симптома (ошибка / таймаут / падение / деградация) | всё, где список пришлось бы выдумывать |

Выдуманный список вреден: он навязывает пользователю чужие названия стендов, а «Other»
превращает вопрос в тот же свободный ввод, только длиннее. Нет источника вариантов —
спрашивай обычным сообщением.

## 2. Откуда берутся варианты

- **Репозиторий.** Имена сервисов из `docker-compose.yml`, `k8s/`, `Makefile`, названий
  модулей и директорий. Стенды — из конфигов окружений, `.env.*`, CI-пайплайнов.
- **База знаний.** Поля `stands` и `services` прошлых записей — там ровно те стенды и
  сервисы, с которыми команда работает: `kb_search.py --list`.
- **Ссылка на систему логов.** Индекс, фильтры, диапазон и имя сервиса закодированы в
  query-параметрах — оттуда же берутся и стенд, и окно времени.
- **Обнаруженные MCP-серверы и CLI.** Список подходящих источников логов сам по себе
  является списком вариантов.

Сообщение пользователя всегда важнее: то, что он уже назвал, не переспрашивается.

## 3. Лимит в 4 вопроса

Инструмент вопроса с вариантами берёт 1–4 вопроса за вызов. Спрашивай **одним вызовом** и только то,
без чего разбор не двинется. Приоритет:

1. **источник логов / способ их передать** — без данных выводов не будет;
2. **стенд** — без него не сузить выгрузку;
3. **сервис** — если не выводится из репозитория однозначно;
4. **окно времени** — если время инцидента вообще не названо.

Остальное уточняется по ходу, когда станет нужно, а не блокирует работу. По одному
вопросу за раз не спрашивай никогда.

## 4. Когда инструмент недоступен

Инструмент вопроса с вариантами есть не во всех режимах запуска (headless,
неинтерактивный вызов).
Тогда задай те же вопросы обычным текстом — одним сообщением, с перечисленными
вариантами в строку. Правила приоритета и «не выдумывать список» остаются в силе.

Разбор из-за недоступности инструмента не останавливается.
