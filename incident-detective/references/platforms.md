# Реестр платформ

Формат Agent Skills общий для нескольких агентных CLI, поэтому поставка у скилла одна:
директория `incident-detective/` копируется в директорию скиллов выбранной платформы.
Различается только обвязка — как называются встроенные инструменты, куда копировать и где
искать подключённые MCP-серверы.

Этот файл — **единственное место платформенных различий**. `SKILL.md` называет инструменты
по назначению и ссылается сюда; добавление платформы — правка этой таблицы и строки в
README, а не текста шагов разбора.

## 1. Имена инструментов по назначению

| Назначение | Qwen Code | GigaCode | Claude Code |
|---|---|---|---|
| ведение списка задач (план работ, шаг 0) | `todo_write` | `todo_write` | `TodoWrite` |
| вопрос с вариантами ответа (шаги 2, 8, 9) | `ask_user_question` | `ask_user_question` | `AskUserQuestion` |
| запуск команд оболочки (скрипты, CLI трекера) | `run_shell_command` | `run_shell_command` | `Bash` |

Не нашёл инструмента с таким именем — ищи по назначению среди доступных, а не пропускай
шаг: обязательность плана работ и вопроса с вариантами от имени инструмента не зависит.

## 2. Директории скиллов

| Платформа | Личная | Проектная |
|---|---|---|
| Qwen Code | `~/.qwen/skills/` | `.qwen/skills/` в корне проекта |
| GigaCode | `~/.gigacode/skills/` | `.gigacode/skills/` в корне проекта |
| Claude Code | `~/.claude/skills/` | `.claude/skills/` в корне проекта |

`$SKILL_DIR` в командах `SKILL.md` — директория, в которую скопирован скилл: например,
`~/.qwen/skills/incident-detective` на Qwen Code, `~/.gigacode/skills/incident-detective`
на GigaCode, `~/.claude/skills/incident-detective` на Claude Code. При проектной установке
путь тот же с точностью до корня проекта вместо `~`.

## 3. Где искать подключённые MCP-серверы и настройки

| Платформа | Команда | Файлы настроек |
|---|---|---|
| Qwen Code | `/mcp` | `.qwen/settings.json`, `~/.qwen/settings.json` |
| GigaCode | `/mcp` | `.gigacode/settings.json`, `~/.gigacode/settings.json` |
| Claude Code | `/mcp` | `.mcp.json` проекта, `.claude/settings.json`, `~/.claude/settings.json` |

## 4. GigaCode — калька Qwen Code

GigaCode устроен в точности как Qwen Code: те же имена инструментов, те же файлы настроек,
тот же формат скиллов. Отличается **только корневой каталог**: везде, где у Qwen Code
`.qwen/`, у GigaCode `.gigacode/`.

Правило записано именно правилом, а не вторым независимым столбцом значений: столбец
разъедется при первой же правке путей Qwen Code, правило — нет. Строки GigaCode в таблицах
выше приведены как раскрытие этого правила, а не как самостоятельный источник.

GigaCode — **целевая платформа**; Qwen Code — платформа разработки и прогонов. При
расхождении приоритет у GigaCode.

## 5. Отличия в возможностях, а не только в именах

- **Вопрос с вариантами берёт 1–4 вопроса за вызов** — на всех трёх платформах. Правила
  приоритета вопросов — [onboarding.md](onboarding.md).
- **Инструмент вопроса доступен не во всех режимах запуска** (headless, неинтерактивный
  вызов). Тогда те же вопросы задаются обычным текстом одним сообщением, с вариантами в
  строку; разбор из-за этого не останавливается.
- **Запуск команд везде подтверждается пользователем** — скрипты скилла на это рассчитаны:
  ничего не выполняется молча, текст тикета показывается до создания.
- **Скрипты контуров платформенно нейтральны:** стандартная библиотека Python 3.8+, без
  сети и внешних зависимостей. Запускаются на любой платформе одинаково.

Замеченное отличие сверх этого списка — вписывать сюда, а не в текст шагов `SKILL.md`.

## 6. Состояние проверки

Платформа считается **проверенной**, когда на ней пройден полный разбор: копирование в
директорию скиллов, самозапуск по описанию инцидента, план работ, вопрос с вариантами,
запуск скриптов, пополнение базы знаний. Чтение реестра проверкой не является — самозапуск
зависит от того, как платформа читает `description`, а это выясняется только запуском.

| Платформа | Полный разбор прогнан | Комментарий |
|---|---|---|
| Qwen Code | да | на ней ведётся разработка, гоняются тесты и `docs/walkthrough.md` |
| GigaCode | **нет** | пути и имена описаны по правилу кальки, CLI в среде разработки не было |
| Claude Code | **нет** | пути и имена описаны, разбор целиком не запускался |

Пометка снимается результатом прогона, а не намерением его выполнить. Строки README о
поддерживаемых платформах правятся вместе с этой таблицей.
