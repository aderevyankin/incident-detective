## Why

Скилл заявлен как переносимый — формат Agent Skills общий для нескольких CLI, — но поставка
привязана к одной платформе. `install.sh:15-20` знает только `~/.qwen/skills` и `.qwen/skills`,
`SKILL.md` вшивает имена инструментов Qwen Code (`todo_write`, `ask_user_question`,
`run_shell_command`), а имя одного из них попало даже в название требования спеки
`incident-detection`. Между тем скилл нужно ставить в три CLI: Qwen Code, Claude Code и GigaCode.

Молчаливая привязка опаснее явного отсутствия поддержки. Обязательный первый шаг разбора —
план работ — назван в спеке через `todo_write`; на платформе, где инструмент называется иначе,
выполнение обязательного требования начинает держаться на догадке модели. Разбор при этом
выглядит нормально, а плана нет.

Отдельная проблема — сам выбор платформы. У пользователя может быть установлено несколько CLI
сразу, и молчаливый выбор одной из них означает, что о промахе он узнает только когда скилл не
запустится там, где ожидался.

Это изменение заменяет предложение `add-claude-code-target`: работа там та же, но платформ три,
а не две, и делать её двумя заходами означает дважды пройти по всем упоминаниям в `SKILL.md` и
по установщику.

## What Changes

- Справочник соответствий платформ в `references/`: назначение инструмента — его имя на каждой
  платформе, каталоги установки, места поиска подключённых MCP-серверов и настроек.
- `SKILL.md` называет инструменты по назначению со ссылкой на справочник вместо вшитых имён.
  Обязательность плана работ и вопроса вариантами при этом не ослабевает.
- **BREAKING** для спеки: требование `incident-detection` «Обязательный план работ через
  `todo_write`» переименовывается — имя платформенного инструмента в названии требования делает
  спеку привязанной к платформе. Поведение скилла не меняется.
- GigaCode вносится третьей платформой. Соответствие принимается полной калькой с Qwen Code —
  каталоги `~/.gigacode/skills` и `.gigacode/skills`, те же имена инструментов, настройки в
  `.gigacode/settings.json` — и помечается в справочнике как принятое по заявлению, а не
  проверенное запуском.
- Установщик получает выбор нескольких платформ сразу, с предвыбором обнаруженных и объявлением
  найденного до вопроса.
- Установщик переносится на Python 3.8+ (только стандартная библиотека), `install.sh` остаётся
  точкой входа и тонкой обёрткой. Интерактивный выбор в bash 3.2 — ручной разбор escape-
  последовательностей и восстановление терминала при прерывании; на Python того же объёма кода
  хватает на работающий селектор, а `python3` для скилла и так обязателен.
- Неинтерактивный путь становится равноправным: `--target qwen,claude`, `--target all`. Когда
  stdin не терминал и цель не задана — ошибка с перечнем допустимых значений, а не зависание на
  ожидании ввода и не молчаливый выбор умолчания.
- `README.md` и `openspec/config.yaml` перестают называть Qwen Code единственной платформой.

## Capabilities

### New Capabilities

Нет. Изменение уточняет упаковку и формулировки уже существующих требований.

### Modified Capabilities

- `skill-packaging`: установка перестаёт быть привязанной к одной платформе — появляются реестр
  платформ, выбор нескольких целей за один запуск, неинтерактивный режим и требование к самому
  установщику по окружению (Python 3.8+, stdlib).
- `incident-detection`: требования о плане работ и о карточке инцидента называют инструменты по
  назначению, а не по имени в Qwen Code.

## Impact

- `install.sh` — сокращается до проверки `python3` и передачи управления.
- `install.py` — новый файл: разбор аргументов, обнаружение платформ, селектор, копирование,
  сохранение записей базы знаний.
- `incident-detective/SKILL.md` — шаги 0, 1, 9, пояснение `$SKILL_DIR`, шаг 3.1 (поиск источников
  логов).
- `incident-detective/references/` — новый справочник платформ; правка `log-sources.md`.
- `README.md` — установка и раздел о поддерживаемых платформах.
- `openspec/config.yaml` — раздел контекста о целевой платформе.
- `openspec/changes/add-claude-code-target/` — удаляется, содержание поглощается этим изменением.

Не затрагивается: скрипты контуров, формат и содержимое базы знаний, поведение разбора.

Пересечение с идущим параллельно `add-kb-location-choice`: оба меняют `README.md` и оба касаются
судьбы базы знаний при переустановке. Установка в три платформы создаёт три копии базы — это
изменение проблему не решает, а делает заметнее; решение целиком остаётся за
`add-kb-location-choice`. Здесь установщик обязан лишь честно сказать, сколько записей он
переносит и куда.
