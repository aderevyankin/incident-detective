## Context

Формат Agent Skills — директория с `SKILL.md` и YAML-фронтматтером — общий для всех трёх целевых
CLI, и это главное, что делает поддержку дешёвой: переносить нужно упаковку и обвязку, а не
содержание.

Различается три вещи:

1. **Куда ставить.** `install.sh:15-20` знает `~/.qwen/skills` и `./.qwen/skills`. У Claude Code
   и GigaCode свои каталоги личных и проектных скиллов.
2. **Как называются инструменты.** `SKILL.md` вшивает `todo_write` (шаг 0), `ask_user_question`
   (шаг 1), `run_shell_command` (шаг 9). Имя поднято в спеку: требование `incident-detection`
   называется «Обязательный план работ через `todo_write`».
3. **Где искать подключённые серверы.** `SKILL.md:119-120` называет `/mcp`, `.qwen/settings.json`,
   `~/.qwen/settings.json`.

Скрипты контуров платформенно нейтральны: чистый Python из stdlib, запускаются одинаково. База
знаний тоже: markdown плюс индекс.

Про GigaCode на момент проектирования известно только заявление владельца задачи: устроен так же,
как Qwen Code. Проверить запуском в среде разработки нельзя — CLI не установлен.

## Goals / Non-Goals

**Goals:**

- Скилл ставится и работает на всех трёх платформах без правки его содержимого руками.
- Обязательные действия скилла — план работ, вопрос вариантами — выполняются на каждой платформе,
  а не полагаются на догадку модели об имени инструмента.
- Установка в несколько платформ выполняется одним запуском, и выбор виден пользователю до
  копирования.
- Установщик не приобретает ни одной внешней зависимости.
- Добавление четвёртой платформы — правка одной таблицы и одного списка, а не `SKILL.md`.

**Non-Goals:**

- Абстракция над различиями платформ в коде: обёртки, адаптеры, слой совместимости. Различия
  описываются текстом.
- Поддержка платформ без формата Agent Skills.
- Изменение поведения скриптов контуров и базы знаний.
- Изменение оснастки OpenSpec в `.claude/` и `.qwen/` — это инструменты разработки проекта, а не
  поставка скилла.
- Выбор расположения базы знаний и раздельные базы по платформам — целиком за
  `add-kb-location-choice`.
- Установка самих CLI и проверка их наличия в `PATH`.

## Decisions

### Инструменты описываются по назначению, имена — в справочнике

`SKILL.md` говорит «инструмент ведения списка задач» и «инструмент вопроса с вариантами ответа»,
а таблица соответствия имён по платформам живёт в отдельном файле `references/`.

Альтернатива «перечислять все имена в каждом упоминании» отвергнута: упоминаний много, текст
раздувается, четвёртая платформа потребует пройти по всем. Альтернатива «оставить имена Qwen Code
и понадеяться, что модель догадается» отвергнута по существу требования: план работ объявлен
обязательным первым действием, и его выполнение не может держаться на догадке.

Меняется формулировка, а не требование. «Первым действием создай список задач» остаётся
обязательным; меняется только то, что инструмент называется по роли. Требование в спеке
`incident-detection` переименовывается по той же причине.

### Реестр платформ — один справочник, установщик его не парсит

Справочник в `references/` — человекочитаемая таблица для модели. Установщик держит собственный
список платформ в коде.

Единственный источник правды здесь выглядит заманчиво, но означает разбор markdown-таблицы в
установщике. Три платформы — это шесть путей; разбор таблицы ради устранения дублирования шести
строк добавляет хрупкости больше, чем снимает. Расхождение ловится отдельной проверкой, которая
сверяет список платформ в установщике с таблицей справочника.

### Одна поставка, а не сборка под платформу

Копируется одна и та же директория скилла. Различия — в путях установки и в справочнике, а не в
содержимом. Отдельные сборки означали бы три версии `SKILL.md`, которые разойдутся: правку внесут
в одну, а проверят на другой.

Плата: справочник соответствий едет в поставке на все платформы, и на каждой две трети таблицы
лишние. Это дешевле расхождения.

### Установщик переносится на Python, `install.sh` остаётся точкой входа

Интерактивный выбор со стрелками в bash — ручной разбор escape-последовательностей через
`read -rsn3`, отрисовка через `tput`, восстановление режима терминала при прерывании. На macOS
системный bash версии 3.2, без ассоциативных массивов, что усложняет и хранение таблицы платформ.
На Python того же объёма кода хватает на работающий селектор: `termios` и `tty` из стандартной
библиотеки, восстановление состояния через `try/finally`.

Решающий довод — `python3` версии 3.8+ и так обязателен для скилла, и установщик уже его
проверяет (`install.sh:31-42`). Новой зависимости не появляется.

`install.sh` сохраняется как точка входа: он документирован в `README.md`, привычен и остаётся
единственной командой, которую нужно знать. Его задача сокращается до проверки наличия `python3`,
проверки версии и передачи управления `install.py` со всеми аргументами. Проверка версии остаётся
в bash намеренно: сообщить «нужен Python 3.8+» должен тот, кто запускается на любой версии.

Альтернатива «оставить всё в bash, а вопрос задавать через `select` или `read`» отвергнута не
из-за внешнего вида: нумерованный ввод не даёт предвыбора обнаруженных платформ и множественного
выбора без отдельного цикла подтверждений.

### Селектор пишется сам, а не берётся из библиотеки

Образцы, на которые опирается решение, оба стоят на npm-пакетах: установщик OpenSpec использует
`@inquirer/core` (`dist/prompts/searchable-multi-select.js`), деплой-скрипт в соседнем проекте —
`@clack/prompts`. Ни то, ни другое неприменимо: скилл строится на отсутствии зависимостей и
рассчитан на закрытые контуры, где `npm install` невозможен. Из образцов берётся поведение, а не
код.

Из установщика OpenSpec (`dist/core/init.js:215-277`):

- обнаруженные платформы предвыбраны, необнаруженные показаны, но не отмечены — их можно выбрать
  осознанно, если CLI будет поставлен позже;
- найденное объявляется текстом **до** списка, а не только галочками в нём;
- неинтерактивный флаг равноправен интерактивному выбору, и при пустом выборе — внятная ошибка со
  списком допустимых значений.

Из соседнего проекта: пояснение к каждому пункту — полный путь установки, и отмена как явное
сообщение с ненулевым кодом возврата, а не молчаливый выход.

Поиска по списку из трёх пунктов не будет: он есть у OpenSpec, потому что там инструментов больше
десятка.

### Неинтерактивный режим — не запасной путь, а равноправный

`--target qwen,claude,gigacode`, `--target all`, в сочетании с `--project`. Скилл разворачивают в
закрытых контурах, по ssh одной командой, из CI. Когда stdin не терминал и цель не задана —
ошибка с перечнем допустимых значений и ненулевой код. Ни зависания на ожидании ввода, ни
молчаливого выбора умолчания: установщик, который в CI тихо выбрал что-то сам, обнаруживается
позже и дороже.

### Автоопределение объявляется, но не решает за пользователя

Платформа считается обнаруженной по существованию её каталога — `~/.qwen`, `~/.claude`,
`~/.gigacode`. Наличие бинаря в `PATH` не проверяется: CLI может быть поставлен как угодно, а
каталог настроек создаётся при первом запуске и потому надёжнее.

Обнаружение задаёт предвыбор, а не результат. Единственная обнаруженная платформа тоже
показывается в списке и подтверждается — иначе пользователь с одним установленным CLI никогда не
увидит, что платформ несколько.

### GigaCode вносится по заявлению, но помечается непроверенным

Соответствие GigaCode принимается калькой с Qwen Code. Проверить в среде разработки нечем, и
делать вид, что проверено, нельзя: `README.md` уже однажды обещал непроверенную поддержку, и это
изменение в том числе чинит.

Поэтому в справочнике у каждой платформы есть состояние: проверено разбором на живом инциденте
или внесено по заявлению. Пометка снимается результатом проверки, а не намерением.

### `$SKILL_DIR` поясняется по платформам

Обозначение `$SKILL_DIR` в командах остаётся — оно и вводилось, чтобы не вшивать путь. Меняется
пояснение: вместо одного пути Qwen Code приводятся пути всех платформ.

## Risks / Trade-offs

**Заявленные пути GigaCode окажутся другими** → Все платформенные различия сведены в реестр и
список в установщике; исправление — правка одной строки в каждом. Пометка «внесено по заявлению»
не даёт принять непроверенное за проверенное.

**Установка в несколько платформ размножает базу знаний** → Установщик называет число переносимых
записей и путь каждой копии, а `README.md` указывает на `INCIDENT_KB_DIR` как на способ иметь одну
базу. Полное решение — за `add-kb-location-choice`.

**Селектор ломается в непривычном терминале** → Интерактивный режим включается только когда stdin
и stdout — терминал; иначе требуется `--target`. Состояние терминала восстанавливается в
`finally`, прерывание обрабатывается явно.

**Windows** → `termios` там недоступен. Установщик определяет это заранее и переходит на
нумерованный ввод. Основной путь поставки — Unix-подобные системы; на Windows скилл
разворачивают копированием директории, для которого установщик не нужен.

**Два источника платформенных данных разойдутся** → Проверка сверяет список в установщике с
таблицей справочника и падает при расхождении.

**Правка `SKILL.md` заденет обязательность плана работ** → Изменение формулировки проверяется
отдельной задачей: обязательность плана и вопроса вариантами должна остаться дословно, меняется
только способ называть инструмент.

## Migration Plan

Изменение обратно совместимо для того, у кого скилл уже стоит: `./install.sh` без аргументов
по-прежнему работает, но теперь показывает выбор вместо молчаливой установки в Qwen Code.

Предложение `add-claude-code-target` удаляется без архивации — оно не реализовывалось, а его
содержание целиком поглощено этим изменением.

## Open Questions

- Каталог скиллов GigaCode принят как `~/.gigacode/skills` и `.gigacode/skills` по аналогии с
  Qwen Code. Подтверждается первой же установкой на машине, где CLI есть.
- Нужен ли `--target none` — установка без копирования, только проверка окружения. Смысл есть
  только если появится сценарий проверки в CI; пока не добавляется.
