## Контекст

Изменение добирает покрытие там, где его нет (контур кода, база знаний, современный
Python), и убирает дубли, накопившиеся в самом наборе. Скрипты не меняются — только
`tests/`, `tools/` не трогаем, CI-матрица.

## Решения

### Генерируемый git-репозиторий для code_hints

В `helpers` появляется `make_repo(tmpdir)`: `git init` + файл с известным классом
исключения (`PaymentPoolExhaustedError` по образцу фикстур) + два коммита с зафиксированными
датами (`GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` из `NOW`) — детерминизм сохраняется.
Тесты: поиск по сигнатуре находит файл; `--repo /nonexistent` и директория без `.git`
дают объяснение и ненулевой код, не трассировку.

### resolve_kb

Прямые тесты через запуск `kb_search.py --list` с комбинациями: только `--kb`; только
`INCIDENT_KB_DIR`; созданная заранее `memory/knowledgebase/` в корне временного «проекта»
(запуск с `cwd` в нём); ничего — база скилла. Отдельно: ступень проекта не срабатывает,
если директории нет, и ничего не создаёт. `helpers.script_env` уже вычищает
`INCIDENT_KB_DIR` — тесты задают её явно.

### kb_add по результату

Запись во временную базу → файл читается обратно `parse_frontmatter`, поля совпадают;
`index.json` содержит запись; повторный `kb_add` в том же месяце — следующий номер id;
предзаполненная чужая запись байт в байт не изменилась.

### Дедупликация набора

- Временная директория: `ScriptCase.tmpdir()` (создание + `addCleanup`) вместо восьми
  копий.
- «JSON в файл»: `helpers.json_to_file(case, tmpdir, name, script, args)`;
  `parsed_to_file` — частный случай.
- `ScriptCase.run_script`/`json_of` перестают дублировать `helpers.run`/`run_json` —
  остаётся один способ.
- Детерминизм: один тест с subTest по списку `(скрипт, аргументы)` — `parse_logs`,
  `trace`, `timeline`, `kb_search`, `confidence`.
- Удаляются тесты-копии эталонов: `test_year_for_timestamp_without_year`,
  `test_no_dominant_error_template`, `test_no_incident_signatures`,
  `test_confidence_stays_low` (его накрывает вариант с базой знаний).
- `tests/run.py`: `check_compatibility()` → вызов `check_compat.main([])`, печать живёт
  в одном месте; на интерпретаторе ниже 3.8 прогон помечается как неполный в stderr.

### CI-матрица

`strategy.matrix.python-version: ['3.8', '3.12']` в существующем job. Плюс гигиена:
`permissions: contents: read`, `timeout-minutes`, `concurrency` с отменой устаревших.

## Риски

- Тесты с git зависят от его наличия в окружении — в CI он есть, локально у
  разработчика скилла тоже (контур кода без git не работает). На машине без git тесты
  контура кода пропускаются с пометкой, как сейчас пропускается проверка совместимости.
- `fix-installer-safety` меняет те же требования `test-harness` (свои сценарии в
  «Обязательные классы проверок» и «Запуск проверок в CI»). Кто архивируется вторым,
  тот сводит оба набора сценариев в требовании руками.
