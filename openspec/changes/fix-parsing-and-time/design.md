## Context

Аудит подтвердил запуском: `parse_logs.py:821-824` считает Python-исключения дважды
(`EXC_RE` и `PY_EXC_RE` пересекаются почти полностью), `parse_logs.py:546-547`
содержит недостижимую проверку (`stripped` после `strip()` не начинается с пробела),
`timeline.py:399-410` помечает коммиты `tz_known: True`, хотя `git log
--date=format:` отдаёт локальное время машины. Остальные пункты — краевые случаи,
на которых разбор либо падает (битый `.xz`), либо молча теряет данные (ротация,
Feb 29, усечение JSON по `--top`).

## Goals / Non-Goals

**Goals:**
- Частоты, сигнатуры и времена, которые видят остальные контуры, соответствуют
  входным данным.
- Ни один из перечисленных краевых случаев не приводит к трассировке или тихой
  потере записей.
- Спека `log-parsing` и код согласованы по статистике при `--level`.

**Non-Goals:**
- Новые флаги и форматы вывода — контракты скриптов не меняются.
- Дедупликация «уложить в бюджет» между скриптами — отдельное изменение
  (dedupe-canons).
- Overflow-файл для parse_logs по образцу timeline/trace — здесь только снятие
  усечения `--top` с JSON; вопрос отдельного файла остаётся за performance-budgets.

## Decisions

- **Исключения: один инкремент на находку.** `PY_EXC_RE` добавляет к `EXC_RE` лишь
  суффикс `Warning` и привязку к началу строки; классы, найденные обеими регулярками
  в одном тексте, объединяются в множество до инкремента счётчиков. Альтернатива —
  слить регулярки в одну — отклонена: пострадает читаемость, а семантика «начало
  строки» у `PY_EXC_RE` нужна.
- **Продолжение строки проверяется по исходному тексту** (`text[0] in ' \t'`), как и
  задумывалось: строка-продолжение не ищет таймстемп вовсе. Это одновременно чинит
  склейку и возвращает докстрингу правдивость.
- **Времена git — через `--date=format-local:` с TZ=UTC в окружении вызова** (или
  `--date=iso-strict` с разбором смещения): один способ на оба потребителя,
  `timeline.py` и `code_hints.py`, чтобы лента и окно `--since/--until` жили в одной
  шкале. Выбор конкретного варианта — за реализацией, критерий: результат не зависит
  от таймзоны машины (проверяется тестом с подменённой TZ).
- **Feb 29 без года**: fallback перебирает назад до ближайшего високосного года, а
  не подставляет заведомо падающий текущий. Допущение фиксируется в сводке тем же
  механизмом, что подстановка года syslog.
- **JSON не усекается `--top`**: `--top` остаётся правилом только md-сводки. Спека
  уже объявляет, что бюджет на JSON не распространяется, — код приводится к ней.
- **Усечение md-сводки**: при нехватке места сохраняется топ по частоте плюс
  гарантированное место для N самых ранних шаблонов (точное правило — в коде рядом с
  `fit_groups`, тест фиксирует, что ранний редкий шаблон переживает усечение).
- **Спека `--level`**: старый сценарий «статистика по всем записям» признаётся
  устаревшим — он несовместим с требованием «Отсев записей до полного разбора»,
  принятым позже и осознанно. Сводка уже честно оговаривает фильтр; спека приводится
  к реальности, а не наоборот.

## Risks / Trade-offs

- [Эталоны тестов зафиксировали удвоенные частоты] → каждый изменяемый
  `tests/expected/*` правится с объяснением, почему новый ответ верен; массовой
  перезаписи нет.
- [`--date=format-local:` зависит от версии git] → проверить на минимально
  поддерживаемой; запасной путь — `iso-strict` с разбором смещения на нашей стороне.
- [Снятие `--top` с JSON увеличит файлы на огромных логах] → JSON и так пишется в
  файл, не в контекст; лимит `--max-lines` остаётся общим потолком.
- [Правка склейки изменит границы записей на экзотических логах] → прогон всех
  фикстур: ожидаемое поведение меняется только там, где раньше запись рвалась
  ошибочно.

## Migration Plan

Правки самодостаточны, флаги не меняются. Порядок: сначала регресс-тест на каждый
пункт (красный), затем правка (зелёный). Откат — реверт коммита изменения целиком.
