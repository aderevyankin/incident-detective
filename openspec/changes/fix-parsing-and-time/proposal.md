## Why

Аудит скриптов нашёл в контуре логов и хронологии дефекты, искажающие данные, на
которых стоят остальные контуры: частоты исключений завышаются вдвое, времена
git-коммитов показываются в ленте под шапкой UTC, будучи локальными, а несколько
краевых случаев роняют разбор или молча теряют данные. Всё это — корректность
фундамента: сигнатуры и хронология питают базу знаний, код и уверенность.

## What Changes

- **Двойной подсчёт классов исключений** (`parse_logs.py`): `EXC_RE` и `PY_EXC_RE`
  находят один и тот же класс и оба инкрементируют счётчик — частоты в сводке,
  сигнатурах и транзитивно в `kb_search`/`confidence` завышены. Каждый класс
  считается один раз.
- **Мёртвая проверка продолжения строки** (`parse_logs.py`): `stripped[0] in ' \t'`
  недостижимо после `strip()` — задумывалась проверка исходного текста. Следствия
  чинятся обе: строки продолжения перестают оплачивать поиск таймстемпа, а отбитая
  пробелами строка с таймстемпом не рвёт склейку многострочной записи.
- **Битый `.xz`/`.lzma` валит разбор**: `lzma.LZMAError` не наследник `OSError` и не
  перехватывается — вместо предупреждения сыплется трассировка.
- **Ротация вида `app.log.1`, `messages.0`** при обходе каталога молча пропускается —
  такие файлы подхватываются наравне с `.log`.
- **«Полный разбор» через `--format json` неполон**: группы режутся `--top`, хотя
  сводка советует JSON как способ увидеть скрытое, а спека объявляет, что бюджет на
  него не распространяется. JSON перестаёт усекаться `--top`.
- **Числовые уровни python logging** (`{"level": 40}`) не распознаются и падают в
  INFO — добавляется соответствие 10..50 → DEBUG..FATAL.
- **Feb 29 без года** при невисокосном «сейчас» теряет таймстемп: fallback подставляет
  тот же год и снова падает — берётся ближайший подходящий високосный год позади.
- **Спека и код разошлись по статистике при `--level`**: старый сценарий требует
  статистику «по всем записям», отсев до разбора (более позднее и осознанное решение)
  делает это невозможным. Спека приводится к поведению отсева с явной оговоркой в
  сводке.
- **Усечение сводки теряет ранние шаблоны**: сортировка только по частоте, «наиболее
  ранние» из требования спеки не сохраняются — правило усечения учитывает и время
  первого появления.
- **Времена git-коммитов в хронологии** (`timeline.py`): `git log --date=format:` даёт
  локальное время машины, но события помечаются `tz_known: True` под шапкой «Времена
  ленты — в UTC»; границы окна `--since/--until` для git трактуются так же локально.
  Времена коммитов приводятся к UTC честно.
- **Отсутствующий файл `--parsed`** в `timeline.py` даёт сырую трассировку вместо
  понятной ошибки, как уже сделано для `--log`.

## Capabilities

### New Capabilities

Нет: изменение чинит поведение до соответствия существующим требованиям.

### Modified Capabilities

- `log-parsing`: сценарий статистики при `--level` согласуется с требованием «Отсев
  записей до полного разбора»; нормализация уровней получает числовые уровни python
  logging; устойчивость парсера покрывает ротированные файлы и битые lzma-архивы
  явными сценариями.

`incident-timeline` не модифицируется: требование единой шкалы UTC уже есть, код
приводится к нему.

## Impact

- `incident-detective/scripts/parse_logs.py` — подсчёт исключений, склейка
  многострочных записей и предфильтр, обход каталога, обработка архивов, JSON-вывод,
  нормализация уровней, разбор syslog-дат, правило усечения сводки.
- `incident-detective/scripts/timeline.py` — время коммитов и границы окна git,
  обработка отсутствующего `--parsed`.
- `incident-detective/scripts/code_hints.py` — формат даты в вызовах `git log`
  (общий с timeline код получения коммитов).
- `tests/` — регресс-тесты на каждый пункт; `tests/expected/*` меняются только там,
  где прежний эталон фиксировал искажённые частоты, с объяснением.
- Флаги и внешние контракты скриптов не меняются; зависимостей не добавляется.
