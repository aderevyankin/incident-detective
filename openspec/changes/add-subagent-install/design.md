## Context

Разбор логов — самый тяжёлый по контексту этап: в основной диалог попадают выгрузки,
промежуточный вывод парсера и черновые гипотезы, хотя для отчёта нужны только сигнатуры и
сжатые итоги. Qwen Code и Claude Code поддерживают субагентов — md-файлы с
YAML-фронтматтером в `.qwen/agents//~/.qwen/agents/` и `.claude/agents//~/.claude/agents/`,
подхватываемые копированием файла. Субагент работает в собственном контексте и возвращает
в родительский диалог только финальный текст.

Сейчас решение не поставляет ни одного определения субагента, а `install.sh` копирует
только директорию скилла. Активное изменение `add-multi-platform-targets` вводит реестр
платформ (Qwen Code, Claude Code, GigaCode) и допущение «GigaCode устроен как Qwen Code,
непроверено» — это изменение строится поверх него.

Решения владельца задачи: субагент один; ставится по умолчанию; имя не должно перетирать
чужих агентов и применяется только для этого скилла; GigaCode — по кальке с Qwen Code, в
директорию `~/.gigacode/agents/` (проектная — `.gigacode/agents/`).

## Goals / Non-Goals

**Goals:**

- Один субагент `incident-detective-log-parser`, выносящий разбор логов из основного
  контекста: на входе пути к логам и карточка инцидента, на выходе сжатый результат
  разбора без сырых дампов.
- Установка субагента по умолчанию тем же `install.sh`, на ту же платформу и в ту же
  область (личная/проектная), что и скилл.
- Полная работоспособность скилла без субагента: делегирование — оптимизация расхода
  контекста, а не условие работы.

**Non-Goals:**

- Субагенты для других контуров (поиск по базе знаний, анализ кода) — дёшевы и без
  делегирования; не плодим сущности без измеримой выгоды.
- Переупаковка решения в расширение Qwen Code или плагин Claude Code — привязала бы
  поставку к платформенным форматам пакетов, а GigaCode их не документирует.
- Оркестрация нескольких параллельных субагентов.
- Фоновое или асинхронное наблюдение за логами — субагент вызывается в рамках обычного
  шага разбора.

## Decisions

### Один субагент — разборщик логов

Делегирование окупается только там, где промежуточные данные объёмны. Это контур логов:
парсер читает мегабайты, а в отчёт идут сигнатуры и счётчики. Поиск по базе знаний ходит
по `index.json`, анализ кода опирается на точечные `git log`/`grep` — их промежуточный
вывод и так мал. Альтернатива «агент на каждый контур» отклонена: три файла в чужих
директориях против одного, а выгода — только у логов.

### Имя с префиксом скилла

Имя субагента — `incident-detective-log-parser`, файл — одноимённый md. Префикс совпадает
с именем скилла, поэтому коллизия с чужим агентом возможна только у другой копии этого же
скилла — а это штатная перезапись. `description` субагента явно ограничивает применение:
вызывается скиллом incident-detective для разбора логов, для других задач не предназначен.
Это снижает шанс, что платформа делегирует ему постороннюю работу по описанию.

### Переносимый фронтматтер без преобразований

Фронтматтер ограничивается пересечением форматов Qwen Code и Claude Code: `name`,
`description`, `tools`. Один и тот же файл копируется на все платформы как есть — тем же
принципом «единая поставка», что и у скилла. Альтернатива с генерацией платформенных
вариантов из шаблона отклонена: полей, ради которых стоило бы различаться, сегодня нет, а
генератор — это новый код и новый класс ошибок.

### Расположение в репозитории: `agents/` в корне

Определение лежит в `agents/incident-detective-log-parser.md` в корне репозитория, рядом с
`incident-detective/`, а не внутри директории скилла. Внутри скилла оно уехало бы в
`~/.qwen/skills/incident-detective/agents/`, где платформа его не ищет, и вводило бы в
заблуждение при ручной установке. Ручная установка агента — то же копирование одного
файла, и README это описывает.

### Установка по умолчанию, той же областью, без молчаливой перезаписи чужого

`install.sh` после успешной установки скилла копирует определение в директорию агентов
той же платформы и той же области: личная установка — `~/.qwen/agents/`,
`~/.claude/agents/`, `~/.gigacode/agents/`; проектная — `.qwen/agents/`,
`.claude/agents/`, `.gigacode/agents/`. Пути берутся из того же реестра платформ, что и
пути скиллов (`add-multi-platform-targets`). Правила:

- Файл с тем же именем и тем же содержимым — молча считается установленным.
- Файл с тем же именем и другим содержимым — перезаписывается только с подтверждением
  (как переустановка скилла); в неинтерактивном режиме — по `--yes`.
- Любая неудача с агентом (нет прав, нет места) не откатывает установку скилла: скилл
  ставится, пользователю объясняется, что субагент не установлен и что это меняет.

Флаг `--no-agents` отключает шаг целиком — для окружений, где писать в директорию агентов
нежелательно. Альтернатива «ставить только по флагу `--with-agents`» отклонена решением
владельца задачи: выгода по умолчанию, отказ — осознанный.

### GigaCode — калька с Qwen Code, с той же пометкой

Публичной документации о пользовательских субагентах GigaCode CLI не найдено. Принимается
то же допущение, что и для путей скиллов в `add-multi-platform-targets`: устроено как в
Qwen Code, директория — `~/.gigacode/agents/`. Пометка «непроверено» обязана появляться в
том же месте реестра, что и для скиллов, чтобы первая проверка на живом CLI закрыла оба
допущения разом. Лишний md-файл в директории, которую CLI не читает, безвреден.

### Контракт делегирования в SKILL.md

`SKILL.md` описывает делегирование как выбор, а не обязанность:

- Субагенту передаются пути к логам (файлы, маски, директории, архивы) и карточка
  инцидента; сами логи в промпт делегирования не вставляются.
- Субагент возвращает результат разбора в формате вывода парсера: сигнатуры, классы
  исключений, счётчики, окна времени, аномалии — и явное «данных нет», если логи пусты
  или нечитаемы. Сырые дампы и построчные цитаты сверх шаблонов сообщений не возвращаются.
- Разбор в основном диалоге остаётся при малом объёме (одна вставка пользователя), при
  отсутствии установленного субагента и при явной просьбе пользователя показать ход
  разбора.
- Результат субагента подчиняется тем же правилам дальнейшего разбора (поиск по базе по
  сигнатурам, скоринг уверенности), что и результат локального запуска парсера.

## Risks / Trade-offs

- **Пути GigaCode окажутся другими** → допущение изолировано в реестре платформ; правка —
  одна строка, пометка «непроверено» уже предупреждает пользователя.
- **Платформа перестанет принимать общий фронтматтер** → полей всего три, все —
  документированное пересечение; при расхождении файл дублируется в реестре платформ, а
  не обрастает генератором.
- **Субагент вернёт сырые дампы и съест выгоду** → контракт возврата зафиксирован в самом
  определении субагента, а спека запрещает возврат дампов; проверяется сценарием спеки.
- **Пользователь не заметит нового файла в `~/.qwen/agents/`** → установщик печатает
  каждый путь, куда положил агента, и упоминает `--no-agents`.
- **Двойной источник правды об именах инструментов парсинга** (SKILL.md и определение
  агента) → определение агента ссылается на те же скрипты `scripts/`, а не дублирует
  инструкции разбора.

## Open Questions

- Нет подтверждённого способа проверить поддержку субагентов GigaCode до первого запуска
  на машине с установленным CLI — закрывается той же ручной проверкой, что заложена в
  `add-multi-platform-targets`.
