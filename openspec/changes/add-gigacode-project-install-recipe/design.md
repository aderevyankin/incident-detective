## Context

Форма артефакта уже правильная: одна директория `incident-detective/` с `SKILL.md`,
`scripts/`, `references/`, `templates/` и `kb/`. Проблема не в составе скилла, а в том,
что инструкция установки начинается с уже существующей локальной копии репозитория.
Сценарий «дай ссылку ассистенту» README называет, но команд под него не даёт.

Действующее требование `openspec/specs/project-documentation/spec.md` запрещает жёсткий URL
внутреннего репозитория в README, поэтому ссылка в рецепте обязана остаться параметром.

## Decisions

### Установка по умолчанию — проектная

```bash
.gigacode/skills/incident-detective/
```

Скилл разбирает инциденты конкретного проекта и копит по нему базу знаний в `kb/`.
В личной директории эта база становится общей на все проекты сразу, что смешивает случаи
разных систем. Проектная установка держит базу там же, где инциденты, и версионируется
вместе с проектом, поэтому она идёт первым примером.

Личная установка остаётся допустимой и обязательной для автономного профиля: там действует
отдельное правило, потому что обвязка разбирает свежий чекаут и не должна зависеть от
доверия к проектной директории.

### Корень скилла определяется поиском, а не именем

Наивные варианты не работают оба. Копирование корня репозитория даёт установку без
`SKILL.md` на ожидаемом месте. Поиск `find . -name SKILL.md` находит в этом репозитории
**13** файлов: целевой и двенадцать в `.qwen/skills/` и `.claude/skills/` — это оснастка
разработки самого проекта, скиллы OpenSpec.

Отсечение служебных точечных директорий оставляет ровно одного кандидата и заодно исключает
`.git` свежего клона:

```bash
find "$TMP" -name SKILL.md -not -path '*/.*/*'
```

Ограничение по глубине сюда не ставится намеренно. У клона скилл лежит на втором уровне,
а у распакованной выгрузки появляется лишний корневой каталог вроде `incident-detective-main/`,
и глубина сдвигается. Отбор по точечным директориям от глубины не зависит и работает в обоих
случаях.

Правило записывается в документацию как «директория с `SKILL.md` вне точечных директорий»,
а не как имя `incident-detective/`: скилл остаётся устанавливаемым и после переименования
или переноса директории внутри репозитория.

### Канонический рецепт

```bash
REPO_URL="<ссылка на репозиторий скилла>"
TMP="$(mktemp -d)"
git clone --depth 1 "$REPO_URL" "$TMP"

SRC="$(dirname "$(find "$TMP" -name SKILL.md -not -path '*/.*/*' | head -1)")"

mkdir -p .gigacode/skills
cp -R "$SRC" .gigacode/skills/
rm -rf "$TMP"
```

Комментарий «корень скилла — директория с `SKILL.md`, а не корень репозитория» остаётся в
тексте команды: это главное, что читатель должен унести.

### Один рецепт для публичного и внутреннего хостинга

Репозиторий скилла может жить и на GitHub, и во внутреннем контуре компании, причём
одновременно: зеркало внутри, публичная копия снаружи. Рецепт не должен раздваиваться из-за
этого, и не раздваивается — ровно потому, что ссылка остаётся параметром. Один и тот же
`REPO_URL` принимает `https://`, `git@`-форму и внутренний хост; всё после получения
репозитория от хостинга не зависит вовсе.

Зашитый URL сломал бы именно этот сценарий: он привязал бы инструкцию к одному из двух
контуров. Действующее требование запрещает жёсткий URL внутреннего репозитория, но и
публичный зашивать не стоит по той же причине.

Различается только способ получить `$TMP`. `git clone` по внутреннему URL может не пройти —
нужна авторизация, VPN или доверие к самоподписанному сертификату. Тогда README называет
равнозначный путь: получить выгрузку репозитория, распаковать во временную директорию,
дальше шаги те же начиная с определения `SRC`. Отдельного второго рецепта не требуется.

## Risks

- **Эвристика поиска ломается молча.** Если в репозитории появится вторая директория с
  `SKILL.md` вне точечных путей, `head -1` выберет произвольную. Пока кандидат один,
  рецепт корректен; при добавлении второго скилла в репозиторий правило придётся уточнить.
- **Проектные скиллы и доверие к директории.** Действующее требование «Установка под
  автономный профиль» фиксирует, что на клиентах семейства Qwen Code загрузка проектных
  скиллов пропускается для недоверенной директории. GigaCode — калька Qwen Code, поэтому
  основной пример может требовать подтверждения доверия к проекту. Поведение проверяется
  задачей, и результат идёт в README оговоркой, если правило подтвердится.
- **Повреждение базы знаний при обновлении.** Проектная установка тоже содержит
  `kb/INC-*.md`; предупреждение про копирование поверх существующей установки сохраняется.
