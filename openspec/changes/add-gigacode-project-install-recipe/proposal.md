## Why

У пользователя на входе обычно только ссылка на репозиторий — свою или чужую он даёт
AI-ассистенту и просит поставить скилл. Репозиторий этого не поддерживает: README
описывает установку как копирование `incident-detective/` из уже имеющейся локальной
копии и не говорит, как получить эту копию и что именно из репозитория является скиллом.

Ловушка здесь не теоретическая. Корень репозитория — не корень скилла: в нём лежат
`README.md`, `tests/`, `tools/`, `openspec/`, и копирование корня в директорию скиллов
даёт установку без `SKILL.md` на ожидаемом месте. При этом наивный поиск «директория, где
лежит `SKILL.md`» тоже промахивается: в репозитории **13** файлов `SKILL.md` — целевой
плюс двенадцать в `.qwen/skills/` и `.claude/skills/`, оснастке разработки самого проекта.
Ассистент, действующий по такому описанию, ставит не то.

Установка по умолчанию — проектная, в `.gigacode/skills/` текущего проекта: скилл
разбирает инциденты конкретного проекта и копит по нему базу знаний, поэтому и жить он
должен рядом с проектом, версионируясь вместе с ним. Личная установка остаётся допустимой
и обязательна для автономного профиля.

## What Changes

- **Рецепт установки по ссылке**: README получает команду, которую ассистент может
  выполнить, имея только URL: клонирование во временную директорию, определение корня
  скилла, копирование в `.gigacode/skills/`, очистка.
- **URL не зашивается**: ссылка остаётся параметром, который даёт пользователь. Это же
  делает рецепт одинаковым для публичного хостинга и внутреннего контура — репозиторий
  может жить и там, и там, вплоть до зеркала внутри и копии снаружи. Жёсткий URL
  внутреннего репозитория в README к тому же запрещён действующим требованием.
- **Корень скилла определяется, а не угадывается**: рецепт находит директорию с `SKILL.md`
  вне служебных точечных директорий, а не полагается на имя `incident-detective/`. Скилл
  ставится и после переименования или переноса директории внутри репозитория.
- **Ветка недоступного клонирования**: для внутреннего репозитория, куда `git clone` не
  проходит без авторизации, README называет путь через выгрузку — дальнейшие шаги те же.
- **Проектная установка — основной пример**: `.gigacode/skills/` идёт первым, личная
  директория остаётся рядом как вариант.

## Capabilities

### New Capabilities

Нет: способ доставки не добавляет скиллу нового runtime-функционала.

### Modified Capabilities

- `skill-packaging`: требование «Установка» дополняется установкой по ссылке на
  репозиторий и правилом, что устанавливается директория с `SKILL.md`, а не корень
  репозитория и не произвольный найденный кандидат.

## Impact

- `README.md` — «Быстрый старт» получает рецепт по ссылке и ставит проектную установку
  первым примером. Правка выполняется в рамках действующего требования
  «Установка описана как получение репозитория и копирование» — оно уже требует описывать
  получение репозитория передачей ссылки ассистенту; собственной дельты `project-documentation`
  изменение не заводит.
- `incident-detective/references/platforms.md` — при необходимости уточняется, что
  проектная директория GigaCode является основным путём установки. GigaCode уже помечен
  в реестре как целевая платформа; роли остальных платформ это изменение не трогает.
- `openspec/specs/skill-packaging/spec.md` — синхронизация дельты после реализации.
- Проверки: `npx @fission-ai/openspec@latest validate --strict`, `python3 tools/check_docs.py`,
  `python3 tests/run.py`.

## Не входит в объём

Перестановка ролей платформ, расширение матрицы на Codex, Gemini CLI и OpenCode, а также
подтверждение XDG-пути GigaCode — самостоятельные вопросы, не мешающие установке по ссылке.
