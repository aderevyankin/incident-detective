# remove-installer — design

## Context

`install.sh` появился как удобство: скопировать скилл в директорию платформы, сохранив
записи базы знаний и отфильтровав артефакты разработки. Вокруг него выросли требования
(атомарная замена, резервные копии, `--yes`, неинтерактивный режим) и тесты
(`tests/test_packaging.py::Installer`, четыре сценария). Модель распространения
изменилась: скилл забирают из внутреннего git-репозитория — выгрузкой или передачей
ссылки AI-ассистенту — и разворачивают копированием директории. README и сам
устанавливал этот способ как равноправный («установщик необязателен»); теперь он
становится единственным.

## Goals / Non-Goals

**Goals:**

- Один документированный способ установки: клонировать репозиторий (или дать ссылку
  ассистенту) и скопировать `incident-detective/` в директорию скиллов платформы.
- Гарантии, которые давал установщик и которые всё ещё нужны, переезжают туда, где
  живут без него: чистота поставки — в содержимое репозитория, сохранность записей
  базы — в документацию и выбор расположения базы.
- Спеки и тесты не описывают ничего, чего в репозитории больше нет.

**Non-Goals:**

- Судьба предложений `add-claude-code-target`, `add-subagent-install`,
  `add-multi-platform-targets` — они построены вокруг установщика и решаются отдельным
  разговором, не этим изменением.
- Автоматизация обновления установленного скилла (git pull в директории скиллов и
  т.п.) — не предлагается и не документируется как рекомендация.
- Изменения самого скилла (`SKILL.md`, скрипты) — не трогаются.

## Decisions

### Ссылка на репозиторий — формулировкой, не URL

README не содержит жёсткого URL внутреннего репозитория: он различается по контурам и
устареет первым. Вместо него — формулировка «клонируйте этот репозиторий или дайте
ссылку на него своему AI-ассистенту»: читатель README уже держит репозиторий (или его
выгрузку) перед глазами, адрес ему известен из того места, откуда он README открыл.
Альтернатива с плейсхолдером `<URL внутреннего репозитория>` отвергнута: плейсхолдер в
командах выглядит как недоделка и провоцирует копировать его буквально.

### Чистота поставки — свойство репозитория, а не шаг установки

Фильтрацию `__pycache__`/`*.pyc` при копировании делал tar внутри установщика. Теперь
инвариант формулируется на уровне версионного контроля: в поставляемой директории
`incident-detective/` нет отслеживаемых артефактов разработки. Проверка в
`tests/test_packaging.py` смотрит на список файлов под версионным контролем
(`git ls-files incident-detective`); без доступного `git` проверка пропускается с
пометкой, а не падает. Локальный `__pycache__` в рабочей копии разработчика при этом
безвреден: в git он не попадает, а у пользователя, взявшего чистую выгрузку, его нет.

### Сохранность записей базы — документацией и выбором расположения

Установщик спасал `kb/INC-*.md` при переустановке. Без него копирование поверх
существующей установки затирает базу внутри директории скилла — молча защитить от этого
нечем, поэтому защита переносится в README: предупреждение в разделе установки
(сохранить записи перед обновлением) и явная рекомендация держать базу снаружи —
`INCIDENT_KB_DIR` или `memory/knowledgebase/` в проекте, — тогда обновление копированием
базу не трогает вовсе. Механизм выбора расположения базы уже есть в скилле и не
меняется.

### Тесты установщика удаляются, а не переписываются

Сценарии `Installer` (чистая поставка через прогон, сохранение записей, `--yes`,
неизвестный аргумент) проверяли поведение скрипта, которого больше нет. Заменяющая
проверка одна — чистота отслеживаемых файлов; остальным сценариям замены не существует
по построению.

## Risks / Trade-offs

- **Обновление копированием затирает базу внутри скилла** → предупреждение в README в
  самом разделе установки, рядом с командой копирования, плюс рекомендация внешнего
  расположения базы. Остаточный риск принят: это цена отказа от скрипта.
- **Пользователь скопирует директорию с локальным `__pycache__`** → безвредно
  (байткод игнорируется), а типовой сценарий — копирование из свежей выгрузки, где
  артефактов нет.
- **Три открытых предложения ссылаются на установщик** → зафиксировано в proposal как
  внешний эффект; их архивация или переработка — отдельное решение пользователя.

## Migration Plan

Изменение одностороннее: файл удаляется, документация и спеки правятся в одном
изменении. У кого скилл уже установлен — ничего не происходит: установленная копия
`install.sh` не содержит. Откат — восстановление файла из git-истории.
