## MODIFIED Requirements

### Requirement: Обязательные классы проверок

Набор проверок SHALL включать разбор с известным ответом, отсутствие ложных срабатываний,
случай несошедшихся контуров, контур кода, базу знаний (запись и разрешение пути) и
чистоту поставляемой директории скилла. Отсутствие любого из этих классов SHALL считаться
неполнотой набора.

#### Scenario: Разбор с известным ответом

- **WHEN** прогон выполняется на фикстуре с заложенным инцидентом
- **THEN** проверяется, что извлечены ожидаемые сигнатуры, определено первое событие и названа
  точка обрыва

#### Scenario: Штатная работа не выдаётся за инцидент

- **WHEN** прогон выполняется на фикстуре без инцидента — с предупреждениями, ретраями и
  единичными клиентскими ошибками
- **THEN** доминирующий шаблон ошибки не выделяется
- **AND** уровень уверенности не поднимается

#### Scenario: Контуры не сошлись

- **WHEN** прогон выполняется на данных, где нет ни совпадения в базе знаний, ни места в коде
- **THEN** уровень уверенности не поднимается выше гипотезы
- **AND** в разборе вкладов названо, каких контуров не хватает

#### Scenario: Контур кода проверяется на подготовленном репозитории

- **WHEN** прогон выполняется на созданном в тесте git-репозитории с известным классом
  исключения
- **THEN** поиск по коду находит файл и место
- **AND** несуществующий репозиторий и директория без `.git` объясняются, а не падают
  трассировкой

#### Scenario: Запись в базу знаний проверяется по результату

- **WHEN** тест выполняет реальную запись в базу во временной директории
- **THEN** файл создан, frontmatter разбирается обратно, индекс обновлён
- **AND** вторая запись в тот же месяц получает следующий id
- **AND** существующие записи не изменяются

#### Scenario: Разрешение пути к базе проверяется на всех ступенях

- **WHEN** тесты задают комбинации `--kb`, `INCIDENT_KB_DIR` и базы в корне проекта
- **THEN** порядок приоритета соблюдается
- **AND** ступень «база в корне проекта» срабатывает только для уже существующей
  директории и ничего не создаёт

#### Scenario: Устойчивость скриптов ко входу

- **WHEN** на вход подан пустой файл, файл без таймстемпов, битая кодировка или чрезмерно
  длинная строка
- **THEN** скрипт завершается штатно с объяснимым выводом, а не трассировкой

#### Scenario: Воспроизводимость

- **WHEN** прогон выполнен дважды на одних данных
- **THEN** результаты совпадают

#### Scenario: Чистота поставляемой директории

- **WHEN** проверяется список файлов `incident-detective/` под версионным контролем
- **THEN** в нём нет `__pycache__`, `*.pyc` и других артефактов разработки
- **AND** при недоступном `git` проверка пропускается с пометкой, а не падает

### Requirement: Запуск проверок в CI

Прогон SHALL выполняться автоматически при изменениях в репозитории. CI SHALL использовать
минимальную поддерживаемую версию Python и SHALL дополнительно выполнять прогон на
современной версии — иначе несовместимость с актуальной stdlib останется незамеченной.

#### Scenario: Запуск на изменение

- **WHEN** выполнен push или открыт pull request
- **THEN** прогон запускается автоматически
- **AND** его падение видно до слияния изменения

#### Scenario: Минимальная версия проверяется

- **WHEN** прогон выполняется в CI
- **THEN** он выполняется на минимальной заявленной версии Python
- **AND** использование более новых возможностей языка обнаруживается прогоном

#### Scenario: Современная версия проверяется

- **WHEN** прогон выполняется в CI
- **THEN** он выполняется и на современной версии Python
- **AND** использование возможностей, удалённых или изменённых в ней, обнаруживается
  прогоном
