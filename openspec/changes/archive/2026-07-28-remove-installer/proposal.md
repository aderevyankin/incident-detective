# remove-installer

## Why

Решено, что скилл распространяется не скриптом, а самим репозиторием: человек выгружает
его из внутреннего git (или даёт ссылку своему AI-ассистенту) и копирует
`incident-detective/` в директорию скиллов платформы. `install.sh` в этой модели —
лишняя движущаяся часть: он дублирует то, что делает `cp -R`, требует терминала и bash,
и держит на себе целый пласт спек и тестов (переустановка, резервные копии базы,
неинтерактивный режим), который больше не нужен.

## What Changes

- **BREAKING** — `install.sh` удаляется. Единственный способ установки — клонировать
  внутренний репозиторий (или дать ссылку на него ассистенту) и скопировать
  `incident-detective/` в директорию скиллов платформы.
- README переписывает «Быстрый старт» под ручную установку: клонирование/выгрузка из
  внутреннего репозитория, копирование, перезапуск CLI. Ссылка на репозиторий — без
  жёсткого URL: формулировка «клонируйте этот репозиторий или дайте ссылку на него
  своему AI-ассистенту».
- README получает явное предупреждение об обновлении поверх существующей установки:
  записи базы знаний `kb/INC-*.md` внутри директории скилла при копировании нужно
  сохранить самому (или держать базу снаружи через `INCIDENT_KB_DIR` /
  `memory/knowledgebase/`) — автоматического спасения записей больше нет.
- Тесты установщика (`tests/test_packaging.py::Installer`) удаляются; проверка чистоты
  поставки (`__pycache__`, `*.pyc` не едут пользователю) переезжает на уровень
  репозитория: артефакты разработки не попадают в git.
- `AI_CONTEXT.md`, `docs/presentation.html` перестают упоминать `install.sh`.
- Спеки `skill-packaging` и `test-harness` приводятся к модели «установка копированием».

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `skill-packaging`: требование «Установка» переписывается — вместо поведения
  установщика (личная/проектная установка, переустановка, резервные копии, флаги,
  неинтерактивный режим) фиксируется распространение репозиторием и установка
  копированием; чистота поставки обеспечивается содержимым репозитория, а не фильтрацией
  при установке. Формулировки «без установщика» в требовании к окружению упрощаются.
- `test-harness`: класс проверок «результат установки» исключается из обязательных;
  вместо него — проверка, что в поставляемой директории скилла нет артефактов
  разработки.
- `project-documentation`: README обязан описывать установку без установщика — включая
  судьбу записей базы знаний при обновлении копированием.

## Impact

- Удаляется: `install.sh`, класс `Installer` в `tests/test_packaging.py`.
- Правится: `README.md` (быстрый старт, платформы, раздел про базу знаний),
  `AI_CONTEXT.md` (раскладка, команды), `docs/presentation.html` (слайд «Установка»,
  список `referenced-files`).
- Спеки: `openspec/specs/skill-packaging/spec.md`, `openspec/specs/test-harness/spec.md`,
  `openspec/specs/project-documentation/spec.md`.
- Незавершённые предложения `add-claude-code-target`, `add-subagent-install`,
  `add-multi-platform-targets` построены вокруг установщика и этим изменением
  обесцениваются — их судьба решается отдельно, здесь они не трогаются.
