## Контекст

`install.sh` — 83 строки bash с `set -euo pipefail`. Найденные дефекты касаются порядка
операций и краевых режимов, а не устройства в целом; менять язык или структуру не нужно.

## Решения

### Атомарная замена вместо `rm -rf` + `cp -R`

Новая копия собирается во временную директорию **на том же файловом томе**, что и место
назначения (`mktemp -d "$DEST_PARENT/.incident-detective.XXXX"`), — иначе `mv` перестаёт
быть атомарным переименованием. Порядок: собрать копию → перенести записи базы → убрать
старую установку → переименовать новую на её место. Единственное окно риска сжимается до
пары `rm`/`mv`; сорванное копирование больше не трогает рабочую установку.

Альтернатива `mv старой в сторону → mv новой на место → rm старой` ещё безопаснее, но
двух временных директорий рядом с целью не хочется; принятое окно риска осознанно мало.

### Чистая поставка

Копирование через `tar -C "$SRC" --exclude='__pycache__' --exclude='*.pyc' -cf - . | tar -xf -`
вместо `cp -R`: переносимо между macOS/Linux и решает фильтрацию штатно. Тест проверяет
результат, а не команду, поэтому способ копирования можно менять свободно.

### Бэкап записей

`mktemp -d` вызывается только когда `INC-*.md` действительно найдены. Путь печатается
сразу после создания. При успешном восстановлении директория удаляется; при сбое остаётся
и её путь уже показан.

### Неинтерактивный режим

Разбор аргументов циклом по `"$@"`: `--project`, `--yes`, `--help`; неизвестное — ошибка
со справкой. Перед `read` — проверка `[ -t 0 ]`: нет TTY и нет `--yes` → понятное
сообщение и выход с ненулевым кодом.

### Тест результата установки

`test_packaging.py` получает тест, который запускает `install.sh </dev/null` с
`HOME=<tmpdir>` (и вторым прогоном — с `--yes` поверх установки с подложенной записью
`INC-*.md`), затем проверяет содержимое `~/.qwen/skills/incident-detective`. Существующий
`test_installer_copies_only_the_skill` (проверка текста скрипта) удаляется. В CI
добавляется шаг с тем же сценарием — фактически тест уже покрывает его через
`tests/run.py`, поэтому отдельный шаг нужен только если тесты установщика решено пометить
как медленные; по умолчанию — не нужен.

## Риски

- `add-multi-platform-targets` / `add-claude-code-target` меняют пути установки в том же
  файле. Конфликт разрешается порядком архивации; настоящее изменение не трогает пути.
- Двойной прогон `kb_index.py` убирается удалением вызова из ветки восстановления —
  безусловный вызов в конце остаётся единственным.
