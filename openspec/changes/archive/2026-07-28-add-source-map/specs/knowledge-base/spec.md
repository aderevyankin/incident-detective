## MODIFIED Requirements

### Requirement: Хранение записей в markdown

База знаний SHALL храниться как markdown-файлы, по файлу на запись. База SHALL хранить
записи двух видов — разбор инцидента и карта источника — и SHALL их различать: вид записи
задаётся явным полем, а поиск и выдача не смешивают их между собой. Файлы SHALL быть
источником правды, а `index.json` — производным артефактом, пересобираемым из них.
Расположение базы SHALL определяться выбором пользователя, а директория внутри скилла
SHALL оставаться значением по умолчанию до того, как выбор сделан.

#### Scenario: Расположение базы

- **WHEN** путь не задан явно и в корне текущего репозитория базы нет
- **THEN** используется директория `kb/` внутри скилла
- **AND** путь переопределяется переменной окружения `INCIDENT_KB_DIR` или флагом `--kb`

#### Scenario: База выбрана в проекте

- **WHEN** путь не задан явно, но в корне текущего репозитория база уже существует
- **THEN** используется она

#### Scenario: Расположение не выбрано

- **WHEN** путь не задан, базы в корне репозитория нет и выбор пользователем ещё не сделан
- **THEN** чтение базы работает с директорией внутри скилла
- **AND** признак «расположение не выбрано» доступен скиллу, чтобы задать вопрос при записи

#### Scenario: Вид записи различается

- **WHEN** индекс пересобирается по базе, где лежат и разборы инцидентов, и карта
  источников
- **THEN** каждая запись получает в индексе свой вид
- **AND** поиск по инцидентам не возвращает записи карты, а запрос карты не возвращает
  разборы

#### Scenario: Запись без явного вида

- **WHEN** в базе оказалась запись, у которой вид не указан
- **THEN** она считается разбором инцидента
- **AND** база, собранная предыдущими версиями скилла, остаётся читаемой

#### Scenario: Индекс пересобирается

- **WHEN** записи правились вручную и запускается `kb_index.py`
- **THEN** `index.json` перестраивается из markdown-файлов
- **AND** содержит перечень записей, а также сводки по тегам, стендам и сервисам

#### Scenario: Индекс потерян

- **WHEN** `index.json` удалён
- **THEN** поиск по базе продолжает работать
- **AND** индекс восстанавливается пересборкой

## ADDED Requirements

### Requirement: Поиск сигнатуры на других стендах

Поиск SHALL поддерживать запрос «та же сигнатура на других стендах» — выдачу записей с
совпадающей сигнатурой, исключая указанный стенд. Выдача SHALL называть стенд каждой
найденной записи, чтобы регрессия, переехавшая между стендами, была видна сразу.

#### Scenario: Ошибка уже встречалась на другом стенде

- **WHEN** запрошена сигнатура с исключением текущего стенда
- **THEN** возвращаются записи с этой сигнатурой по остальным стендам
- **AND** у каждой названы стенд, дата и исход

#### Scenario: Совпадений на других стендах нет

- **WHEN** сигнатура встречалась только на исключённом стенде
- **THEN** выдача пуста
- **AND** это сообщается как «на других стендах не встречалась», а не как отсутствие
  записей вообще

#### Scenario: Стенд не указан

- **WHEN** запрос сделан без указания исключаемого стенда
- **THEN** поиск ведёт себя как обычный поиск по сигнатуре
- **AND** ошибкой это не считается
