## Context

Скилл уже умеет разбирать логи (`parse_logs.py`), искать в базе знаний
(`kb_search.py`), связывать ошибку с кодом (`code_hints.py`) и строить
хронологию (`timeline.py`). Все они работают через общий JSON-обмен: парсер
отдаёт `--format json`, остальные читают его через `--from-parsed`.

Два новых механизма встраиваются в ту же схему: `trace.py` читает сырые логи
через модуль `parse_logs`, `confidence.py` — JSON-артефакты остальных скриптов.
Ограничения платформы прежние: Python 3.8+, только стандартная библиотека, без
сети, работа локально на файлах.

## Goals / Non-Goals

**Goals:**

- Собрать цепочку запроса через несколько сервисов по correlation id и назвать
  сервис, где всё началось.
- Дать разбору численную опору: сколько независимых контуров сошлось на выводе.
- Сохранить принцип «наблюдаемое отдельно от предполагаемого» — новые механизмы
  должны его усиливать, а не подменять красивым числом.

**Non-Goals:**

- Не строим полноценный distributed tracing: span-дерево, родитель-потомок,
  OpenTelemetry. Работаем тем, что реально попадает в логи стендов.
- Не делаем real-time обнаружение и не подключаем внешние трейсинг-системы —
  скилл остаётся локальным и on-demand.
- Не автоматизируем вывод причины: оценка уверенности сопровождает вывод модели,
  а не заменяет его.

## Decisions

**Точка обрыва — самая ранняя ошибка, а не первый хоп.** Порядок хопов и порядок
ошибок расходятся: вызывающий сервис пишет свой таймаут позже, чем упал
вызванный. Сортировка ошибок по времени по всей цепочке даёт кандидата в
причину, а хопы остаются для понимания структуры вызова.

**Часы правятся только вручную.** Расхождение оценивается по разнице первых
отметок общих запросов: устойчивое значение при малом разбросе похоже на сдвиг
часов, гуляющее — на реальную задержку. Но отличить сдвиг от стабильной
задержки в принципе нельзя, поэтому автоматическая коррекция подставила бы в
отчёт время, которого не было в логах. Скрипт показывает оценку и готовую
строку `--offset`, применяет её пользователь.

**Вес одного контура — не больше 0.30 при пороге 0.70.** Так ни один источник в
одиночку не даёт «подтверждено данными»: даже стопроцентное совпадение с
записью базы знаний остаётся «вероятной причиной», пока его не поддержали логи
или код. Это прямое следствие принципа скилла — не выдавать догадку за вывод.

**Отсутствующий контур не перераспределяет вес.** Иначе разбор по одним логам
получал бы высокую уверенность просто потому, что больше ничего не проверяли.
Непроверенный контур обнуляет свой вклад и попадает в раздел «что поднимет
уверенность» с готовой командой.

**Артефакты вместо запуска чужих скриптов.** `confidence.py` не вызывает
`kb_search.py` и `code_hints.py` сам, а читает их JSON. Каждый шаг остаётся
проверяемым по отдельности, а оценка считается по тем же данным, которые модель
уже видела в разборе.

**Метка сервиса в аргументе источника.** Формат `--log сервис=путь` — метка
попадает в цепочку и в вывод. Без неё берётся имя файла, и вместо
`gateway → payment` получается `gw.log → pay.log`.

## Risks / Trade-offs

- **Число выглядит объективнее, чем оно есть.** Веса подобраны экспертно, а не
  выведены из статистики. Смягчается тем, что оценка никогда не выводится без
  разбора вкладов словами: читать нужно объяснение, число — только сводка.
- **Оценка часов косвенная.** Стабильная сетевая задержка неотличима от сдвига
  часов. Смягчается формулировкой вывода и требованием сверяться с системным
  временем стендов.
- **Цепочка неполна при потере id.** На очередях, ретраях и фоновых задачах
  идентификатор часто теряется, и обрыв цепочки на брокере можно принять за
  поломку брокера. Оговорено в справочнике и в выводе.
- **Ещё два скрипта в разборе.** Растёт число шагов, которые модель должна
  пройти. Смягчается тем, что оба необязательны: цепочка нужна только для
  межсервисных инцидентов, оценка уверенности — только перед выводом.
