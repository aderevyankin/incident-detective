# add-trace-and-confidence

## Why

Скилл разбирает инцидент по трём контурам, но два разрыва остаются.

**Первый — межсервисный.** Логи каждого сервиса разбираются отдельно, и когда
падение проходит через цепочку (gateway → payment → inventory), по отдельным
сводкам все виноваты одинаково: у одного `504 upstream timed out`, у другого
`SQLTimeoutException`. Кто из них упал первым, а кто отреагировал на чужой
сбой, приходится выяснять глазами по времени — при том, что сервисы уже
передают друг другу correlation id и пишут его в каждую строку.

**Второй — в честности вывода.** Правило «разделяй наблюдаемое и
предполагаемое» есть в SKILL.md, но опирается только на дисциплину модели.
Вывод, собранный по одному совпадению в базе знаний, и вывод, где сошлись
логи, код и цепочка запроса, выглядят в отчёте одинаково уверенно.

Разбор в [issue #1](https://github.com/aderevyankin/incident-triage-skill/issues/1)
называет оба места и предлагает готовые механизмы: сквозной трейсинг по
correlation id и численную оценку уверенности вывода.

## What Changes

- Новый контур **сквозной цепочки запроса**: `scripts/trace.py` сводит логи
  нескольких сервисов в одну цепочку хопов по correlation id, показывает паузы
  между сервисами и первую по времени ошибку как точку обрыва.
- Оценка **расхождения часов** между сервисами по общим запросам
  (`--check-clocks`) и ручная поправка (`--offset`). Автоматически время не
  правится: в отчёте не должно появляться время, которого не было в логах.
- Новый шаг **оценки уверенности**: `scripts/confidence.py` считает, на скольких
  независимых контурах стоит вывод, и переводит это в уровень «подтверждено
  данными / вероятная причина / гипотеза» с разбором вклада каждого контура.
- Шаг 6 (вывод) в `SKILL.md` привязывает формулировку причины к полученному
  уровню, а не к ощущению модели.
- Справочник `references/correlation.md` — как работает сквозной id, что читать
  в цепочке и где у метода границы.

## Capabilities

### New Capabilities

- `correlation-tracing`: сборка сквозной цепочки запроса по correlation id через
  логи нескольких сервисов, поиск точки обрыва, оценка расхождения часов.
- `confidence-scoring`: численная оценка уверенности в выводе по числу
  сошедшихся контуров и объяснение вклада каждого из них.

### Modified Capabilities

- `incident-reporting`: формулировка причины в отчёте привязывается к
  полученному уровню уверенности, а не остаётся на усмотрение модели.

## Impact

- Затронутые спеки: `correlation-tracing` (новая), `confidence-scoring`
  (новая), `incident-reporting` (пополняется требованием об уровне уверенности).
- Затронутый код: `incident-triage/scripts/trace.py`,
  `incident-triage/scripts/confidence.py`, `incident-triage/SKILL.md`,
  `incident-triage/references/correlation.md`, `README.md`.
- Обратная совместимость полная: существующие скрипты и формат базы знаний не
  меняются, оба новых скрипта работают на артефактах, которые уже производятся.
- Ограничение платформы сохраняется: Python 3.8+, только стандартная библиотека,
  без сети.
