## Why

`README.md` — единственный вход в проект для человека, который скилл ещё не видел. Сейчас он
на 320 строк и растёт от изменения к изменению: каждое предложение дописывает в него свой
раздел, потому что нигде не сказано, что README содержит, а что нет. Отсюда три беды.

**Он говорит от имени одной платформы.** Заголовок называет Qwen Code CLI, ссылка ведёт на её
документацию, примеры запуска скриптов начинаются с `S=~/.qwen/skills/incident-detective/scripts`.
Пользователь другой платформы не понимает, относится ли к нему написанное.

**Он рассказывает, но не показывает.** Есть перечень скриптов и флагов, есть описание контуров
и уверенности, но нет ни одного сквозного примера: что ввёл человек, что скилл ответил, что
получилось в итоге. Прочитавший README знает устройство скилла и не знает, как выглядит разбор.

**Он не проверяется ничем.** Числа бюджетов, перечень capability, список файлов в разделе
«Структура», команды в примерах — всё это устаревает молча. Раздел «Структура» уже перечисляет
файлы вручную; любой новый скрипт делает его неверным, и заметить это можно только глазами.

Отдельно: README не сообщает читателю самого нужного — как за пять минут увидеть скилл в
работе, ничего не ломая. Материал для этого в репозитории есть: синтетические фикстуры в
`tests/fixtures/logs/` дают воспроизводимый разбор с заранее известным ответом.

## What Changes

- README получает заданную структуру: что обязано быть, в каком порядке и с какой глубиной.
  Дальше он пополняется по этой структуре, а не дописыванием разделов в конец.
- Быстрый старт с выбором платформы вместо установки от имени Qwen Code.
- Раздел поддерживаемых платформ с честным состоянием проверки каждой.
- Примеры запуска скриптов переводятся на `$SKILL_DIR` — без пути одной платформы.
- Новый документ `docs/walkthrough.md`: сквозной разбор от вставленного стектрейса до записи в
  базу знаний, целиком на фикстурах репозитория, так что читатель повторяет каждую команду и
  получает тот же вывод.
- README сокращается за счёт переноса подробностей в `docs/walkthrough.md` и `references/`:
  точка входа должна оставаться обозримой, как и `SKILL.md`.
- Проверка README в `tools/`: команды из примеров запускаются, перечень capability сверяется с
  `openspec/specs/`, дерево файлов в разделе «Структура» — с содержимым репозитория.
- Правило поддержки: изменение, меняющее установку, состав скриптов, capability или числовые
  бюджеты, обязано поправить README в том же изменении.

## Capabilities

### New Capabilities

- `project-documentation`: что README и сопутствующие документы репозитория обязаны содержать,
  как они проверяются на актуальность и когда обязаны обновляться.

### Modified Capabilities

Нет.

## Impact

- `README.md` — переработка структуры и содержания.
- `docs/walkthrough.md` — новый файл.
- `tools/check_docs.py` — новая проверка, включается в общий прогон `tests/run.py`.
- `tests/fixtures/logs/` — используется как материал для walkthrough; при необходимости
  добавляется фикстура, дающая полный разбор со всеми тремя контурами.

Не затрагивается: `SKILL.md`, `references/` скилла, скрипты, спецификации поведения разбора.

**Пересечения с параллельной работой.** `README.md` правят также `add-kb-location-choice`
(раздел базы знаний) и `add-multi-platform-targets` (установка и платформы). Это изменение
идёт после них и вбирает их правки в общую структуру, а не переписывает поверх: иначе
конфликты придётся разбирать трижды. Проверка из `tools/` заводится в его составе, поэтому до
её появления актуальность README держится на внимании.
