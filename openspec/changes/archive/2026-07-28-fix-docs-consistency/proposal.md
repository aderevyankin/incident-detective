## Why

Документация повторяет сама себя, и копии уже расходятся молча — ни один прогон этого не
ловит:

- Порядок разрешения пути к базе знаний описан в **пяти** местах (README, AI_CONTEXT,
  SKILL.md, `references/kb-format.md`, `kb/README.md`); таблица «трёх контуров» — в
  четырёх; раздел «Границы» — в четырёх формулировках.
- Команда предпроверки окружения существует в двух версиях и **уже разошлась**: в
  `SKILL.md` к ней дописан вызов `kb_search.py`, в `references/limited-mode.md` — нет,
  хотя файл позиционирует себя как её описание.
- `.claude/skills/` и `.qwen/skills/` — **побайтово идентичные копии** шести скиллов
  OpenSpec; правка одной молча разъедется со второй.
- Найденные фактические ошибки: таблица capability в README перечисляет 12 из 13 спек
  (потерян `runtime-preflight`); `references/next-step.md` отсылает к «уровню уверенности
  шага 6», тогда как уверенность считается на шаге 4 — прямая дезориентация агента;
  в перечне `templates/` README не хватает `kb-entry-example.md`; `AI_CONTEXT` называет
  4 команды `/opsx:*` из 6 установленных.

Для агента, читающего SKILL.md по ходу разбора, расхождение между двумя копиями одного
правила — не косметика: какую копию он прочтёт, так и поступит.

## What Changes

- У каждого повторяющегося правила появляется **один канонический дом**, остальные места
  заменяются короткой ссылкой:
  - порядок разрешения пути к базе — `references/kb-format.md`;
  - команда предпроверки — `references/limited-mode.md`, SKILL.md ссылается;
  - «Границы» — полный текст в SKILL.md (его читает агент), README и AI_CONTEXT дают
    сжатую версию со ссылкой;
  - таблица контуров остаётся в README и SKILL.md (это вход в оба документа), но
    объявляется, что канон — SKILL.md.
- Дублирующиеся куски `references/onboarding.md` и `references/limited-mode.md`,
  пересказывающие SKILL.md, заменяются ссылками — в references остаётся только то, чего
  в SKILL.md нет.
- Фактические правки: `runtime-preflight` в таблицу capability; «шага 6» → «шага 4» в
  `next-step.md`; `kb-entry-example.md` в перечень `templates/`; полный список команд
  `/opsx:*` в AI_CONTEXT; один способ вызова `openspec validate` в README и AI_CONTEXT.
- `.claude/` и `.qwen/`-копии скиллов OpenSpec: фиксируется, что источник — `.qwen/`, а
  `.claude/` — производная; появляется проверка синхронности в `tests/run.py` (сравнение
  содержимого), чтобы расхождение перестало быть молчаливым. В README/AI_CONTEXT — одна
  фраза, что это оснастка разработки, а не поставка скилла.
- Дублирование текста таблицы «контур/вопрос/скрипты» и «Границ» в `openspec/config.yaml`
  сокращается до ссылки на SKILL.md.

## Capabilities

### New Capabilities

_нет — требования добавляются в существующую спеку `project-documentation`._

### Modified Capabilities

- `project-documentation`: единый канонический дом для повторяющихся правил; проверка
  синхронности производных копий; перекрёстные ссылки вместо копий.

## Impact

- `README.md`, `AI_CONTEXT.md`, `incident-detective/SKILL.md`,
  `incident-detective/references/*.md`, `incident-detective/kb/README.md`,
  `openspec/config.yaml` — замена копий ссылками, фактические правки.
- `tests/run.py` — проверка синхронности `.claude/` ↔ `.qwen/`.
- Внешних зависимостей нет: спека `project-documentation` уже введена архивированным
  `add-readme-maintenance`.
- Поведение скриптов не меняется.
