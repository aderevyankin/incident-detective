## Контекст

Изменение почти целиком внутреннее: сведение четырёх копий разбора времени, четырёх копий
укладки в бюджет и рассыпанных констант к одному источнику в `kb_common.py`. Поведение
наружу меняется только там, где копии уже разошлись в дефект: `--since 1h` в
`timeline`/`code_hints`, безлимитный вывод `trace`/`timeline`, превышение `--max-chars`
в `triage`, потеря JSON-записей префильтром.

## Решения

### Разбор времени: переезд `parse_time_arg` в `kb_common`

Канонической берётся реализация из `parse_logs.py` — единственная, знающая относительные
окна. Она переезжает в `kb_common.parse_time_arg`; `parse_logs` реэкспортирует для
обратной совместимости внутренних вызовов. `timeline.parse_dt`, инлайновый `strptime` в
`code_hints` и «свои» форматы `_parse_now` сводятся к ней. `_parse_now` остаётся отдельным
(у него жёстче контракт: неразобранное значение — ошибка запуска), но список форматов
берёт из того же места.

### Укладка в бюджет: `kb_common.fit_by_render`

Общая функция: список элементов + рендер элемента + бюджет + резерв под хвост; возвращает
(показанные, скрытые). Четыре существующие реализации переводятся на неё, сохраняя свои
тексты «не показано …» и приоритеты элементов. `limit_frames` в `code_hints` перестаёт
мутировать `data`: количество скрытых фреймов возвращается и кладётся в JSON всегда, а не
только на пути `md`. `trace.py`/`timeline.py` получают тот же предел `MAX_SUMMARY_CHARS`
с записью полного результата в файл — по образцу `parse_logs --out`.

В `triage.fit_output` убирается гарантия «первый раздел целиком»: первый раздел проходит
через ту же укладку, что и остальные, с резервом под заголовки последующих.

### `triage` → `kb_search`

Из `kb_search` выделяются `query_from_parsed(parsed)` и `rank(incidents, query,
min_score)`; `triage.py` вызывает их. Фильтр служебных сервисов (`access`) закрепляется в
`query_from_parsed` — единственное место, где он теперь живёт (поведение `kb_add`
включается в общий путь осознанно, это и есть устранение расхождения).

### Константы

`EXC_RE` (полный вариант с `Denied|Refused`), `LEVELS`, `LEVEL_ORD`, `DEFAULT_MAX_LINES`
переезжают в `kb_common`. `parse_logs` и `code_hints` импортируют оттуда; `confidence` и
`triage` перестают импортировать `parse_logs` целиком.

### Префильтр JSON

В `PreFilter` уровень не проверяется для строк, начинающихся с `{` после `lstrip()`:
такие строки идут в полный разбор, где уровень достаётся из поля. Отсев по времени и
`--grep` для них сохраняется — там таких ложных срабатываний нет (таймстемп в JSON
распознаётся тем же `find_timestamp`, подстрока — честный поиск).

### Преамбула и json

Преамбула сводится к `sys.path.insert(...)` + `from kb_common import require_python;
require_python()`. `kb_common.dump_json(obj, path_or_stream)` с `default=str` и едиными
`ensure_ascii=False, indent` заменяет десять вызовов; `chain_to_json` в `trace.py`
удаляется.

### bench.py

Окружение собирается по образцу `tests/helpers.script_env`: фиксированный
`INCIDENT_NOW`, `PYTHONDONTWRITEBYTECODE=1`, вычищенные `INCIDENT_*`. Замер `code_hints`
переводится на генерируемый git-репозиторий (init + два коммита в директории бенчмарка —
как в тестах). Мёртвые ветки (`ORDER`, «triage.py ещё не реализован») удаляются, `--only`
валидируется по `BUDGETS`, паттерн «посчитай, если нет файла» сводится к одной функции
`ensure(path, cmd)`.

## Риски

- Самый чувствительный участок — префильтр: любое изменение грозит либо потерей записей,
  либо потерей скорости. Скорость контролируется `tools/bench.py` (бюджеты ≥50k строк/с),
  корректность — новой фикстурой с JSON-строками.
- Перевод `trace`/`timeline` на бюджет меняет их вывод на больших входах. Это желаемое
  изменение, но тесты на «дважды запусти — сравни» должны гоняться на входах меньше
  бюджета, чтобы не завязаться на текст усечения.
- `fix-timestamp-correctness` (активное изменение) правит те же места разбора времени.
  Порядок: сначала оно, затем это — сведение копий переносит уже исправленное поведение,
  а не наоборот.
