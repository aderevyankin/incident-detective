## Context

Формат Agent Skills — директория с `SKILL.md` и YAML-фронтматтером — общий для всех трёх
целевых CLI, и это главное, что делает поддержку дешёвой: переносить нужно обвязку, а не
содержание.

После `remove-installer` установка на любой платформе одинакова — копирование
`incident-detective/` в её директорию скиллов. Различается три вещи:

1. **Куда копировать.** У Qwen Code, Claude Code и GigaCode свои каталоги личных и
   проектных скиллов.
2. **Как называются инструменты.** `SKILL.md` вшивает `todo_write` (шаг 0),
   `ask_user_question` (шаг 1), `run_shell_command` (шаг 9). Имя поднято в спеку:
   требование `incident-detection` называется «Обязательный план работ через `todo_write`».
3. **Где искать подключённые серверы.** `SKILL.md` называет `/mcp`, `.qwen/settings.json`,
   `~/.qwen/settings.json`.

Скрипты контуров платформенно нейтральны: чистый Python из stdlib, запускаются одинаково.
База знаний тоже: markdown плюс индекс.

GigaCode — целевая платформа, и владелец задачи зафиксировал её устройство: полная калька
Qwen Code, отличается только корневой каталог — `.gigacode/` вместо `.qwen/`
(`~/.gigacode/skills`, `.gigacode/skills`, `.gigacode/settings.json`), имена инструментов
те же. Разработка и прогоны идут на Qwen Code; при расхождении приоритет у GigaCode.
Прогнать разбор на самом GigaCode в среде разработки нельзя — CLI не установлен, и это
касается только состояния проверки, а не соответствия путей.

## Goals / Non-Goals

**Goals:**

- Скилл разворачивается и работает на всех трёх платформах без правки его содержимого
  руками.
- Обязательные действия скилла — план работ, вопрос вариантами — выполняются на каждой
  платформе, а не полагаются на догадку модели об имени инструмента.
- Все платформенные различия сведены в одно место — реестр в `references/`.
- Добавление четвёртой платформы — правка реестра и строки в README, а не `SKILL.md`.

**Non-Goals:**

- Возврат установщика в любом виде — модель «распространение репозиторием, установка
  копированием» зафиксирована `remove-installer` и здесь не пересматривается.
- Абстракция над различиями платформ в коде: обёртки, адаптеры, слой совместимости.
  Различия описываются текстом.
- Поддержка платформ без формата Agent Skills.
- Изменение поведения скриптов контуров и базы знаний.
- Изменение оснастки OpenSpec в `.claude/` и `.qwen/` — это инструменты разработки
  проекта, а не поставка скилла.
- Установка самих CLI и проверка их наличия в `PATH`.

## Decisions

### Инструменты описываются по назначению, имена — в реестре

`SKILL.md` говорит «инструмент ведения списка задач» и «инструмент вопроса с вариантами
ответа», а таблица соответствия имён по платформам живёт в отдельном файле `references/`.

Альтернатива «перечислять все имена в каждом упоминании» отвергнута: упоминаний много,
текст раздувается, четвёртая платформа потребует пройти по всем. Альтернатива «оставить
имена Qwen Code и понадеяться, что модель догадается» отвергнута по существу требования:
план работ объявлен обязательным первым действием, и его выполнение не может держаться на
догадке.

Меняется формулировка, а не требование. «Первым действием создай список задач» остаётся
обязательным; меняется только то, что инструмент называется по роли. Требование в спеке
`incident-detection` переименовывается по той же причине.

### Реестр платформ — единственное место платформенных различий

Реестр в `references/` — человекочитаемая таблица для модели и для человека,
разворачивающего скилл: имена инструментов, директории скиллов, места поиска серверов,
состояние проверки. Без установщика второго списка платформ в коде больше нет, и сверять
реестр не с чем — он единственный источник, и это снимает риск расхождения целиком.

Плата: реестр едет в поставке на все платформы, и на каждой две трети таблицы лишние.
Это дешевле расхождения, которое возникло бы у платформенных вариантов поставки.

### Одна поставка, а не сборка под платформу

Копируется одна и та же директория скилла. Различия — в реестре, а не в содержимом.
Отдельные сборки означали бы три версии `SKILL.md`, которые разойдутся: правку внесут в
одну, а проверят на другой.

### GigaCode — калька Qwen Code с другим корневым каталогом

Соответствие GigaCode задано владельцем задачи и заводится в реестр как факт: всё
совпадает с Qwen Code, кроме корневого каталога. Правило записывается именно так — «везде,
где `.qwen/`, у GigaCode `.gigacode/`», — а не как второй независимый столбец значений:
столбец разъедется при первой же правке, правило — нет.

Отдельно от соответствия живёт **состояние проверки**: прогнан ли на платформе полный
разбор. У GigaCode CLI в среде разработки нет, поэтому состояние остаётся «не
прогонялось», и `README.md` этого не скрывает — он уже однажды обещал непроверенную
поддержку, и это изменение в том числе чинит. Пометка снимается результатом прогона, а не
намерением.

### `$SKILL_DIR` поясняется по платформам

Обозначение `$SKILL_DIR` в командах остаётся — оно и вводилось, чтобы не вшивать путь.
Меняется пояснение: вместо одного пути Qwen Code приводятся пути всех платформ.

### Поддержка объявляется после проверки, а не после написания текста

Платформа считается **проверенной**, когда на ней пройден разбор целиком: самозапуск по
описанию инцидента, план работ, вопрос с вариантами, запуск скриптов, пополнение базы
знаний. Каждый из этих шагов задействует платформенный механизм, и ни один не проверяется
чтением реестра. Это не формальность: самозапуск зависит от того, как платформа читает
`description`, — то есть от того, что нельзя проверить иначе, чем запуском.

## Risks / Trade-offs

**Пути GigaCode окажутся не полной калькой** → Все платформенные различия сведены в
реестр; исправление — правка одной строки. Состояние «полный разбор не прогонялся» не даёт
принять непроверенное за проверенное.

**Копирование в несколько платформ размножает базу знаний** → `README.md` указывает на
`INCIDENT_KB_DIR` как на способ иметь одну базу на все платформы; предупреждение об
обновлении копированием уже стоит в разделе установки.

**Правка `SKILL.md` заденет обязательность плана работ** → Изменение формулировки
проверяется отдельной задачей: обязательность плана и вопроса вариантами должна остаться
дословно, меняется только способ называть инструмент.

**Описание по назначению окажется расплывчатым и модель выберет не тот инструмент** →
Описание сопровождается прямой отсылкой к реестру, где имена перечислены точно.

## Migration Plan

Для того, у кого скилл уже развёрнут, ничего не меняется: содержимое директории скилла
обновляется обычным копированием новой версии. Предложение `add-claude-code-target`
удалено без архивации — оно не реализовывалось, а его содержание целиком поглощено этим
изменением.

Изменение считается выполненным по реестру, тексту и документации. Прогон разбора на
платформах — отдельная задача, которая снимает пометки состояния в реестре по мере того,
как соответствующий CLI оказывается под рукой; отсутствие GigaCode на машине разработки
не держит изменение в незавершённых.
