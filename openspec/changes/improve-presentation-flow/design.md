## Context

`docs/presentation.html` — один самодостаточный файл: слайды на HTML/CSS, навигация
на встроенном JS, числовые утверждения продублированы в JSON-блоке
`<script id="facts">`, который `tools/check_docs.py` сверяет с исходниками по
`SOURCE_PATTERNS`. Нынешние десять слайдов выстроены как питч: два слайда боли,
затем архитектура, демо, числа, границы, установка на три платформы. Решение
пользователя: зритель — человек с уже сформированной болью, нашедший скилл;
презентация должна отвечать «почему именно этот и что я получу», слайды боли —
лишние, установка — только GigaCode, нужны примеры использования обоих режимов.

## Goals / Non-Goals

**Goals:**
- Каждый слайд отвечает на вопрос зрителя, выбирающего инструмент: что это, как
  работает, почему верить, чем отличается, что получу, что ещё внутри, как поставить.
- Оба режима использования показаны примерами: диалоговый на фикстурах, автономный
  от алерта до `report.json`.
- Инварианты сохранены: один файл, без сети и сборки, печать, числа с инструментом
  получения, зелёные `check_docs.py` и `tests/run.py`.

**Non-Goals:**
- Таблица «три контура» — зона `dedupe-canons`; здесь слайд 3 пересказывает смысл
  («сошедшиеся контуры»), не копируя таблицу.
- Реализация автономного режима — зона `add-aiops-mode`; здесь только его показ.
- Изменение README сверх путей установки; таблица платформ README остаётся.
- Правки скриптов и `check_docs.py` (кроме случая привязки проверок к именам
  удаляемых слайдов).

## Decisions

- **Целевой состав — девять слайдов**: 1) что это — одна фраза; 2) как проходит
  разбор — воркфлоу; 3) почему выводу можно верить — уверенность как свойство;
  4) чем отличается от «вставить лог в чат»; 5) пример: диалоговый разбор на
  фикстурах; 6) пример: AIOps от алерта до `report.json`; 7) что ещё внутри — база
  знаний, карта источников, ограниченный режим, телеметрия; 8) свойства и границы;
  9) установка GigaCode. Слайды «Инцидент на стенде» и «Почему разбор дорог»
  удаляются: доказательство проблемы зрителю с болью не нужно.
- **Форма воркфлоу — нумерованная цепочка, не SVG-диаграмма**: дешевле для печати и
  обеих тем, содержание то же. Точки решения помечаются в цепочке: предпроверка
  (полный/ограниченный режим), карта источников (прямой заход вместо перебора),
  уровень уверенности (формулировка и ведущий следующий шаг). Порядок объясняется
  бюджетом пяти вызовов — переиспользуется существующий факт из `facts`, новых
  чисел не добавляется.
- **AIOps-слайд показывает контракт, а не обещание**: вход (payload алерта), запуск
  (готовая команда в изолированной среде), выход (`report.json`: вердикт, уверенность,
  доказательства, черновик следующего шага), условие применения (ночь, человека нет,
  среда ограничена снаружи). Конкретный вывод и числа включаются только когда
  воспроизводимы на материалах репозитория — то есть по готовности `add-aiops-mode`;
  его задача 6.4 исполняется здесь, одним заходом в презентацию. До того слайд
  описывает вход/выход/условие без невоспроизводимых чисел — требование «числа только
  с инструментом получения» не нарушается.
- **«Что ещё внутри» — не перечень умений, а три-четыре свойства с их смыслом**
  (почему второй инцидент дешевле первого). Формулировка «перечень возможностей не
  заменяет изложение» в спеке сохраняется — слайд строится вокруг выгоды, а не списка.
- **Слияние «Скорость в цифрах» и «Что скилл не делает»**: оба отвечают на один
  вопрос зрителя — «какие у него свойства и пределы»; числа и их источники
  сохраняются как есть, чтобы не трогать `facts`.
- **Установка — только GigaCode на слайде**: две команды `cp -R` (личная и проектная
  директории), перезапуск CLI, `/skills`. Таблица трёх платформ со слайда уходит —
  выбор платформы это вопрос README, а не десятиминутного показа. В README основной
  пример тоже `.gigacode`; строка Qwen Code в таблице платформ остаётся (тесты идут
  на ней — честность сохраняется). Пути оснастки разработки (`.qwen/commands/`,
  `.claude/`) примерами установки не считаются и не правятся.

## Risks / Trade-offs

- [AIOps-слайд до завершения add-aiops-mode описывает контракт без живого вывода] →
  порядок применения: пути установки и перекомпоновку можно делать сразу, финальное
  наполнение AIOps-слайда — после сквозного прогона add-aiops-mode (задача 7.4 там);
  слайд не публикует чисел, пока их нечем подтвердить.
- [Пересечение с dedupe-canons в presentation.html] → зоны разделены: здесь
  перекомпоновка слайдов, там таблица контуров; при последовательном применении
  конфликт только текстуальный.
- [test_presentation.py/check_docs могут быть привязаны к удаляемым слайдам] →
  прогон в задачах; правка проверок допускается только в части имён слайдов, не
  ослабляя сверку фактов.
- [Слайд воркфлоу перегружен текстом] → критерий приёмки: один экран, печать —
  слайд на страницу.

## Migration Plan

Правки только в презентации и README. Порядок: перекомпоновка слайдов → пути
установки → прогон `check_docs.py` и `tests/run.py`; наполнение AIOps-слайда живым
выводом — по готовности `add-aiops-mode`. Откат — реверт коммита.
