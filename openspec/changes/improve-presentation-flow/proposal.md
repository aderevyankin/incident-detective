## Why

Презентация построена как питч «докажи, что проблема существует»: два первых слайда
продают боль инцидентов человеку, которого надо убеждать. Реальный зритель другой —
у него боль уже есть и скилл он уже нашёл; его вопросы: почему именно этот, как он
работает, что я получу и что ещё внутри. На эти вопросы презентация не отвечает: хода
разбора нет, примеров использования нет, база знаний и карта источников — самые
сильные продуктовые аргументы — не упомянуты вовсе. Вдобавок примеры установки ведут
в `.qwen/`, хотя целевая платформа — GigaCode.

## What Changes

- **Ось изложения меняется**: с «зачем такой скилл нужен миру» на «почему тебе стоит
  поставить именно этот». Слайды «Инцидент на стенде» и «Почему разбор дорог»
  удаляются — что инциденты это плохо, всем понятно; первый содержательный слайд
  одной фразой говорит, что делает скилл.
- **Новый слайд «Как проходит разбор»** — воркфлоу агента: план → карточка →
  источники → разбор одной командой (логи → база знаний → код → уверенность) →
  чтение кода → вывод → пополнение базы → следующий шаг; точки решения (предпроверка,
  карта источников, уровень уверенности) помечены в цепочке; порядок объясняется
  бюджетом пяти вызовов (факт уже есть в блоке `facts`).
- **Уверенность переакцентируется**: из схемы архитектуры в свойство продукта «почему
  выводу можно верить»; слайд «Чем отличается от вопроса модели напрямую» поднимается
  выше — это ядро дифференциации.
- **Примеры использования, два режима**: диалоговый — существующий разбор на фикстурах;
  автономный (AIOps) — алерт → запуск в изолированной среде → `report.json` с
  вердиктом: вход, выход, условие применения.
- **Новый слайд «Что ещё внутри»**: база знаний (второй такой же инцидент начинается
  с готового ответа), карта источников (второй разбор дешевле первого), ограниченный
  режим, телеметрия контуров.
- **«Скорость в цифрах» и «Что скилл не делает» сливаются** в слайд свойств и границ:
  локально, stdlib, без сети, числа из `bench.py`; не рестартует, не гадает, секреты
  не пишет.
- **Установка — только GigaCode**: команды `cp -R` в `~/.gigacode/skills/` и
  `.gigacode/skills/`; таблица трёх платформ со слайда уходит (остаётся в README).
  В README «Быстрый старт» и примере `$SKILL_DIR` основной путь тоже становится
  `.gigacode`; строка Qwen Code в таблице платформ README сохраняется.
- Инварианты презентации не меняются: один файл, без сети и сборки, печать, каждое
  число с инструментом получения, блок `facts` сверяется `tools/check_docs.py`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `project-presentation`: требование «Состав и порядок изложения» переписывается под
  зрителя со сформированной потребностью — без слайдов боли, с ходом разбора, отличием
  от прямого вопроса модели, примерами обоих режимов, ценностью повторного разбора и
  установкой только для целевой платформы.
- `project-documentation`: основной пример установки во всей документации — путь
  целевой платформы (`.gigacode/`); пути оснастки разработки примерами установки не
  считаются.

## Impact

- `docs/presentation.html` — перекомпоновка: минус два слайда боли, плюс слайды хода
  разбора, AIOps-примера и «что ещё внутри», слияние скорости с границами, слайд
  установки только GigaCode. Блок `facts` — без новых непроверяемых чисел.
- `README.md` — «Быстрый старт» и пример пути `$SKILL_DIR` на `.gigacode`; таблица
  платформ не меняется по составу.
- `tests/test_presentation.py`, `tools/check_docs.py` — прогоняются; правок не
  ожидается, кроме случая, если проверка привязана к именам удаляемых слайдов.
- Координация: содержимое AIOps-слайда (команда, вывод `report.json`) становится
  воспроизводимым по завершении `add-aiops-mode` — его задача 6.4 «слайды автономного
  сценария» исполняется в рамках этого изменения, чтобы презентацию не перекраивать
  дважды. Таблицу контуров приводит к канону `dedupe-canons` — здесь не трогается.
