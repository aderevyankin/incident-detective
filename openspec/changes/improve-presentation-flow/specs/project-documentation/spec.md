## MODIFIED Requirements

### Requirement: README не привязан к одной платформе

`README.md` SHALL описывать установку и запуск для каждой поддерживаемой платформы. Примеры
команд SHALL NOT содержать путь установки одной платформы там, где команда одинакова для всех.
Основной пример установки SHALL показывать путь целевой платформы — GigaCode
(`.gigacode/skills/`); это правило SHALL распространяться на примеры установки во всей
документации репозитория, включая презентацию и сквозной разбор. Qwen Code SHALL оставаться
в перечне платформ с честным указанием, что разработка и проверка идут на ней.

#### Scenario: Установка приведена для каждой платформы

- **WHEN** читатель ищет команду установки
- **THEN** приведён способ выбрать платформу
- **AND** ни одна платформа не выдаётся за единственную

#### Scenario: Основной пример установки — целевая платформа

- **WHEN** документ репозитория показывает пример команды установки
- **THEN** путь примера — директория скиллов GigaCode (`~/.gigacode/skills/` или
  `.gigacode/skills/` проекта)
- **AND** рядом указан способ выбрать другую платформу

#### Scenario: Пути оснастки разработки не считаются примерами установки

- **WHEN** документ упоминает `.qwen/commands/`, `.claude/` или `.qwen/` как оснастку
  разработки самого репозитория
- **THEN** такие упоминания примерами установки не считаются
- **AND** на пути GigaCode не переводятся

#### Scenario: Примеры запуска скриптов платформенно нейтральны

- **WHEN** README показывает запуск скрипта вне агента
- **THEN** путь обозначается как `$SKILL_DIR`
- **AND** пояснение к обозначению даётся один раз

#### Scenario: Состояние проверки платформы названо

- **WHEN** README перечисляет поддерживаемые платформы
- **THEN** по каждой указано, проверялся ли на ней полный разбор
