## Context

Спека project-documentation требует «один канонический дом у повторяющегося правила», и
после dedupe-script-internals у скриптов появился общий модуль `kb_common`. Аудит
показал, что принцип соблюдается точечно, а не системно: таблица трёх контуров живёт в
четырёх местах тремя вариантами (канон `SKILL.md` называет `kb_search`+`kb_add`, README
и `AI_CONTEXT.md` добавляют `kb_index`, презентация оставляет только `kb_search`), при
этом README сам декларирует «расходиться им нельзя», а `check_docs.py` текстовую
синхронность не проверяет. `SKILL.md` вырос до ~620 строк и на ~80–100 строк состоит из
пересказов собственных references. В коде живут четыре реализации «уложить вывод в
бюджет» при каноне `kb_common.fit_by_render`, `grep_repo` в `code_hints.py` на каждый
вызов заново обходит и читает весь репозиторий (до 7 раз за `build` — против бюджета
≤3 с). Спеки log-ingestion и source-map описывают порядок discovery дважды,
runtime-preflight и confidence-scoring дважды описывают учёт ручного разбора.

Аудит делался по состоянию до add-aiops-mode; номера строк сместились, но все находки
подтверждены на текущем дереве, кроме одной: у `kb_common.KB_FLAG`/`KB_ENV` потребитель
появился (`kb_add.py`, автономный режим) — находка снята.

## Goals / Non-Goals

**Goals:**
- У каждого повторяющегося правила — ровно один канонический дом; копии становятся
  ссылками или заведомо сжатыми пересказами со ссылкой.
- Синхронность оставшихся витринных копий (таблица контуров) проверяется прогоном,
  а не дисциплиной.
- Клоны «уложить в бюджет», рендера и разбора аргументов сведены к одной реализации.
- **Ключевой инвариант: поведение агента и скриптов не меняется.** Устраняются только
  копии; каждое правило остаётся в каноне. `tests/run.py` и `check_docs.py` зелёные,
  `bench.py` не хуже.

**Non-Goals:**
- Новые правила, флаги, форматы вывода — ничего не добавляется по существу.
- Правка канонов по содержанию: если копии расходятся, выравнивание идёт по канону,
  а не поиском «лучшей» версии.
- Переписывание references — они и есть каноны, их текст не трогается (кроме пометок).

## Decisions

- **Канон таблицы трёх контуров — `SKILL.md`.** README это уже декларирует («правится
  сначала он»), и именно по SKILL.md работает агент. Копии выравниваются по нему:
  контур базы знаний — `kb_search.py`, `kb_add.py` **без** `kb_index.py` (индекс —
  служебная пересборка, а не инструмент контура; README и AI_CONTEXT упоминают его в
  своих разделах про устройство базы, этого достаточно). Презентация дополняется до
  полного состава. Альтернатива — выровнять по README (с `kb_index`) — отклонена:
  канон объявлен, и правило «правится сначала канон» обесценивается, если при первом
  же расхождении побеждает копия.
- **Синхронность таблицы проверяет `check_docs.py`.** Проверка парсит таблицу канона
  (строки `| **N. Имя** | … | … |`) и сверяет перечень контуров и состав скриптов с
  README, AI_CONTEXT и таблицей презентации. Сверка по составу, не по байтам: витринные
  копии вправе отличаться формулировкой вопроса и оформлением, но не составом скриптов.
  Альтернатива — генерировать копии из канона — отклонена: три документа с разным
  оформлением ради одной таблицы не стоят генератора.
- **`templates/incident.md` удаляется.** Это сирота: ни один скрипт, документ или тест
  на него не ссылается (единственное упоминание — дерево файлов в README), структуру
  записи канонизирует `kb-format.md#структура-записи`, живой пример — рядом лежащий
  `kb-entry-example.md`, а записи создаёт `kb_add.py`, который шаблон не читает.
  Альтернатива — оставить и сослаться из `kb-format.md` — отклонена: это третья копия
  структуры записи, которую пришлось бы включать в проверку синхронности. Дерево файлов
  в README правится в том же изменении — `check_docs.check_structure` иначе упадёт.
- **Канон «GigaCode — калька Qwen Code» — `AI_CONTEXT.md`.** Это контекст для агентов,
  который читается всеми (симлинки AGENTS.md, GIGACODE.md). README (раздел платформ) и
  `openspec/config.yaml` (context) оставляют по одной сжатой фразе со ссылкой на
  AI_CONTEXT; полная формулировка с перечнем отличий — только в каноне.
- **Сжатие SKILL.md — ссылками, не выбрасыванием.** Каждый снимаемый фрагмент обязан
  иметь канон, и ссылка на него остаётся в том же месте шага: правила отличительных
  признаков — один полный текст (в шаге 4, где данные для проверки уже есть), в шаге 1 —
  одна строка со ссылкой; «лишняя задача — лишний проход модели» произносится один раз
  (шаг 0), остальные вхождения опираются на уже сказанное; пересказ onboarding.md в
  шаге 2 сжимается до правила «спрашивай одним вызовом, закрытые списки — вариантами»
  плюс ссылка; список ключевых слов в шаге 3 заменяется ссылкой на
  `log-sources.md#5-сопоставление-по-ключевым-словам`; шаг 8 «Где держать базу»
  сжимается до триггера (код 3), формы вопроса и ссылки на `kb-format.md#где-лежит-база`;
  правила ограниченного режима сводятся к одному упоминанию на шаг со ссылкой на
  `limited-mode.md` §4–5; перечень маскируемых данных во всех трёх местах заменяется
  ссылкой на `kb-format.md#маскирование` (перечень видов и форма меток — только там).
  Требования спек при этом не теряются: каждое правило остаётся нормативным в каноне,
  SKILL.md сохраняет сам шаг и ссылку.
- **`walkthrough.md` хранит копию плана с пометкой о каноне.** План в walkthrough —
  часть воспроизводимого сквозного разбора, убирать его нельзя; добавляется строка
  «канон плана — шаг 0 SKILL.md, правится сначала он». В проверку синхронности таблиц
  план не включается: walkthrough фиксирует конкретный прогон, а не витрину.
- **Бюджетные клоны сводятся к `fit_by_render`.** `parse_logs.fit_groups` и
  inline-цикл `kb_search` — прямая замена (рендер уже есть: `render_groups`/`render_hit`).
  `code_hints.limit_frames` сохраняет сигнатуру и смысл (возврат числа скрытых для
  JSON), но внутри считает через `fit_by_render`; эвристика `budget*2//3` выражается
  через параметры вызова, итоговые выводы на фикстурах не меняются (проверяется
  эталонами). Двойной вызов `limit_frames` за запуск устраняется: `build()` считает
  один раз и передаёт результат рендеру.
- **`timeline.render_md` рендерит через `render_event`.** Gap-суффикс `(+span)`
  передаётся в рендер параметром/полем события, а замер бюджета в `fit_by_render`
  выполняется тем же рендером с суффиксом — сейчас замер занижает объём, и лента может
  вылезать за бюджет.
- **`grep_repo` получает кэш содержимого на процесс.** Обход `walk_code` и чтение
  файлов выполняются один раз за запуск (`build` вызывает grep до 7 раз), поиск идёт по
  кэшу. Результаты не меняются — меняется только число чтений; `bench.py` станет
  быстрее, что допустимо (сравнением сводок фиксируется «не хуже, результат тот же»).
- **Разбор `%h|%ad|%an|%s` — одна функция** (`_parse_commit_lines`), используют
  `commits_in_window` и `file_history`.
- **`parse_source_arg` переезжает в `kb_common`** (или общий модуль разбора аргументов),
  `trace.py` и оба места `timeline.main` используют его. Поведение inline-варианта чуть
  отличалось (не срезал расширение у метки) — сохраняется поведение канона
  `parse_source_arg`; тесты `test_trace_timeline` фиксируют, что метки источников в
  выводе не изменились для случаев с явным `label=`.
- **`Group.traces` удаляется** — копится и нигде не выводится; `--trace` работает
  другим путём. Мёртвое поле, а не резерв: резерв без потребителя — тот же дубль.
- **`KB_FLAG`/`KB_ENV` остаются.** Находка аудита устарела: `kb_add.py` в автономном
  режиме различает источник пути по этим константам.
- **`test_presentation.py` перестаёт гонять `check_docs` целиком.** `run.py` уже
  вызывает `check_docs.main([])` — полный прогон в тесте дублируется. Остаются:
  `test_file_exists` и один тест на `check_presentation(failures)` (точечная проверка
  презентационных фактов с внятным сообщением об ошибке); `test_main_returns_zero`
  удаляется. Покрытие сохраняется: сам `main([])` исполняется в `run.py`, и его падение
  валит прогон.
- **Спеки: канон discovery — source-map, канон учёта ручного разбора —
  confidence-scoring.** source-map владеет картой и порядком (полный порядок 1–4 уже
  там); требование «Карта читается до перебора каналов» вливается в «Порядок
  обследования» (REMOVED с переносом всех сценариев, «Пара картой не покрыта» покрыт
  «Дошли до перебора»). log-ingestion сохраняет своё: что искать среди имеющегося и
  запрет своего MCP — но порядок и полный список ключевых слов отдаёт канонам
  (source-map и `log-sources.md` §5). runtime-preflight оставляет правило подачи
  («результат — наблюдение»), а учёт при оценке уверенности остаётся только в
  confidence-scoring — тот не модифицируется: он и есть канон.

## Risks / Trade-offs

- [Сжатие SKILL.md потеряет нормативное правило] → перед снятием каждого фрагмента
  правило находится в каноне (или переносится туда дословно в том же коммите); в
  SKILL.md остаётся ссылка. Сверка — по перечню находок аудита, пункт за пунктом.
- [Замена limit_frames/fit_groups изменит границу усечения на краевых данных] →
  эталоны `tests/expected/*` не правятся; расхождение эталона — сигнал, что замена не
  эквивалентна, и подгоняется реализация, а не эталон.
- [Проверка синхронности таблицы окажется хрупкой к оформлению] → сверка по составу
  (имена контуров и скриптов), а не по байтам; парсер таблицы терпит **жирный**,
  нумерацию и порядок колонок.
- [Кэш grep_repo изменит результаты при повторных вызовах с другим limit] → кэшируется
  только содержимое файлов, не результаты поиска; limit применяется поверх кэша как
  раньше.
- [Удаление incident.md сломает чей-то внешний процесс] → шаблон не упоминается нигде,
  кроме дерева README; в README-дереве строка удаляется, `check_docs` подтверждает
  согласованность. Восстановление — `git revert`.
- [Слияние требований source-map потеряет сценарий при архивации] → REMOVED содержит
  Migration с поимённым перечнем перенесённых сценариев; `validate --strict` в задачах.

## Migration Plan

Изменение самодостаточно, контракты скриптов и поведение агента не меняются. Порядок:
сначала спековые дельты и проверка синхронности таблицы (она красная на текущих
копиях), затем выравнивание копий и сжатие документов, затем код с регресс-тестами,
в конце — сравнение сводок `bench.py` до/после. Откат — реверт коммита целиком.
