## Why

`README.md` называет среди целевых платформ Claude Code, но поставить туда скилл нечем.
`install.sh:15-20` знает ровно два пути: `~/.qwen/skills` и `./.qwen/skills`. Спека
`skill-packaging` требует пояснять, что `$SKILL_DIR` — это «обычно `~/.qwen/skills/incident-triage`»,
и `SKILL.md:22` так и написан. Пользователь Claude Code, следуя README, получает скилл, который не
устанавливается и в инструкциях которого путь ведёт не туда.

Хуже, чем пути, — имена инструментов. `SKILL.md` вшивает в текст конкретные имена: план работ
создаётся «инструментом `todo_write`» (шаг 0), уточняющие вопросы задаются «одним вызовом
`ask_user_question`» (шаг 1), команды выполняются через `run_shell_command` (шаг 9). Эти имена
подняты в спеки: требование в `incident-detection` так и называется — «Обязательный план работ
через `todo_write`». В Claude Code инструменты называются иначе. Модель, скорее всего, догадается
по смыслу, — но скилл, который держится на догадке о названии обязательного инструмента, не
выполняет собственное требование «первым действием создай план».

Поиск источника логов вшит так же: `SKILL.md:119-120` предлагает смотреть `/mcp` и
`.qwen/settings.json` — файлы, которых на другой платформе нет.

Наконец, `.claude/` в репозитории заполнена, но не тем: там команды и скиллы OpenSpec — оснастка
разработки самого проекта, а не поставка incident-triage. Их наличие создаёт ложное впечатление,
что поддержка есть.

## What Changes

- Установщик умеет ставить скилл **в директорию скиллов Claude Code** — личную и проектную,
  наряду с существующими путями Qwen Code. Выбор платформы задаётся явно; при отсутствии указания
  установщик определяет платформу по тому, что есть в системе, и **называет свой выбор** до
  копирования.
- Скилл ставится **в обе платформы**, если обе присутствуют и пользователь этого хочет: команда
  работает в разных средах, и делить базу знаний по платформам смысла нет.
- `SKILL.md` перестаёт вшивать **имена инструментов конкретной платформы**. Требуемое действие
  описывается по назначению — «инструмент ведения списка задач», «инструмент вопроса с
  вариантами», — а конкретные имена по платформам выносятся в отдельный справочный файл. Требование
  остаётся прежним по сути: план обязателен, вопросы задаются вариантами.
- То же для **пути к скиллу**: `$SKILL_DIR` перестаёт объясняться через один путь Qwen Code,
  пояснение даётся по платформам.
- То же для **поиска источника логов**: перечень мест, где смотреть подключённые серверы,
  приводится по платформам, а не только для Qwen Code.
- В `README.md` появляется **установка для каждой платформы** и явное указание, что общего между
  ними и что различается.
- **Проверка на обеих платформах** становится обязательной частью изменения: скилл не считается
  поддерживающим платформу, пока на ней не выполнен разбор от самозапуска до пополнения базы
  знаний.
- Оснастка OpenSpec в `.claude/` **не трогается**: это инструменты разработки проекта, к поставке
  скилла они отношения не имеют, и путать их с ней не нужно.

## Capabilities

### Modified Capabilities

- `skill-packaging`: формат и установка перестают быть привязаны к одной платформе; вводится
  требование описывать инструменты по назначению, а конкретные имена держать в справочнике по
  платформам; установщик поддерживает обе платформы и объявляет выбранную.
- `incident-detection`: требование обязательного плана работ формулируется через назначение
  инструмента, а не через его имя в конкретной платформе.

## Impact

- `install.sh`: выбор платформы, пути установки Claude Code, определение платформы по умолчанию с
  объявлением выбора, установка в обе платформы.
- `incident-triage/SKILL.md`: замена вшитых имён инструментов на описание по назначению, пояснение
  `$SKILL_DIR` по платформам, поиск источника логов по платформам.
- `incident-triage/references/`: новый справочный файл соответствия инструментов и путей по
  платформам.
- `incident-triage/references/log-sources.md`: места поиска подключённых серверов для обеих
  платформ.
- `README.md`: установка и различия по платформам, честный перечень поддерживаемого.
- `openspec/config.yaml`: раздел контекста, где целевой платформой названа только Qwen Code.
- Формат Agent Skills общий для обеих платформ, поэтому структура директории скилла не меняется.
- База знаний, скрипты и их поведение не меняются.
