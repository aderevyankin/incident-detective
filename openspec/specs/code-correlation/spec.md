# code-correlation

## Purpose

Третий контур: связь ошибки из логов с местом в коде проекта и с git-историей. Скрипт
собирает материал — фреймы стектрейсов, место порождения текста ошибки, коммиты в окне
инцидента — а выводы и предложения по правкам делает модель.

## Requirements

### Requirement: Разбор фреймов стектрейсов

Скрипт SHALL извлекать ссылки на файлы и строки из стектрейсов распространённых языков и
сопоставлять их с файлами репозитория.

#### Scenario: Поддерживаемые языки

- **WHEN** во входных данных есть стектрейс Java, Kotlin, Python, JavaScript,
  TypeScript, Go, C#, PHP или Ruby
- **THEN** из него извлекаются имя файла, номер строки и, если есть, имя символа

#### Scenario: Файл найден в проекте

- **WHEN** имя файла из фрейма совпало с файлом репозитория
- **THEN** выводится путь, строки вокруг указанной с пометкой целевой строки и результат
  `git blame` этой строки

#### Scenario: Несколько кандидатов

- **WHEN** в репозитории несколько файлов с одинаковым именем
- **THEN** кандидаты упорядочиваются по совпадению хвоста исходного пути
- **AND** остальные варианты перечисляются

#### Scenario: Файл не найден в проекте

- **WHEN** файла из фрейма нет в репозитории
- **THEN** это сообщается как результат — код внешней библиотеки или другого сервиса

#### Scenario: Строки нет в файле

- **WHEN** номер строки превышает длину найденного файла
- **THEN** выводится предупреждение, что код в репозитории не той версии, что на стенде
- **AND** предлагается сверить ветку или тег с задеплоенной сборкой

### Requirement: Поиск места порождения текста ошибки

Скрипт SHALL искать в коде проекта литеральные фрагменты сообщения об ошибке, чтобы
находить источник даже при отсутствии стектрейса.

#### Scenario: Фрагменты берутся из шаблона

- **WHEN** сигнатура содержит плейсхолдеры
- **THEN** для поиска используются части шаблона между плейсхолдерами, достаточно длинные
  и осмысленные

#### Scenario: Совпадение найдено

- **WHEN** фрагмент найден в файле проекта
- **THEN** выводится путь, номер строки, сама строка и фрагмент, по которому нашлось

#### Scenario: Совпадений нет

- **WHEN** ни один фрагмент не найден в проекте
- **THEN** сообщается, что сообщение приходит из библиотеки, соседнего сервиса или
  инфраструктуры
- **AND** перечисляется, что именно искали

#### Scenario: Служебные директории пропускаются

- **WHEN** выполняется обход репозитория
- **THEN** каталоги вроде `.git`, `node_modules`, `venv`, `dist`, `build`, `target`
  исключаются
- **AND** чрезмерно большие файлы пропускаются

### Requirement: Сопоставление с git-историей

Скрипт SHALL выводить коммиты за сутки до первой ошибки. Отсутствие git SHALL NOT
приводить к сбою.

#### Scenario: Окно считается по первой ошибке

- **WHEN** в разборе есть группы уровня WARN и выше
- **THEN** началом окна берётся время первой такой группы, а не первой записи лога

#### Scenario: Коммиты найдены

- **WHEN** в окне есть коммиты
- **THEN** выводятся хеш, дата, автор и заголовок каждого
- **AND** сопровождается предупреждением, что совпадение по времени не доказательство

#### Scenario: Коммитов нет

- **WHEN** в окне коммитов не найдено
- **THEN** это трактуется как сигнал: причина, вероятно, не в свежем коде, а в конфиге,
  данных, нагрузке или соседнем сервисе

#### Scenario: Проект не под git

- **WHEN** директория не является git-репозиторием
- **THEN** разделы про коммиты и blame пропускаются
- **AND** остальной анализ выполняется

### Requirement: Способы подачи входных данных

Скрипт SHALL принимать входные данные из разбора логов, из файла, строкой аргумента или
из стандартного ввода.

#### Scenario: Из разбора логов

- **WHEN** задан `--from-parsed <файл>`
- **THEN** используются шаблоны, сигнатуры, классы исключений и временное окно разбора

#### Scenario: Из текста или потока

- **WHEN** задан `--text` или данные поданы в stdin
- **THEN** стектрейс разбирается напрямую без предварительного парсинга логов

### Requirement: Разграничение диагностики и правок

Скрипт SHALL только собирать материал и SHALL NOT изменять код. Скилл SHALL предлагать
правки лишь после подтверждения причины и SHALL NOT применять их молча.

#### Scenario: Скрипт не меняет файлы

- **WHEN** анализ выполнен
- **THEN** файлы проекта остаются без изменений

#### Scenario: Правка предлагается после причины

- **WHEN** механизм отказа ещё не подтверждён
- **THEN** скилл не предлагает патч
- **AND** сначала объясняет, чего не хватает для вывода

#### Scenario: Правка объясняется

- **WHEN** правка предлагается
- **THEN** показывается изменение и объясняется, что оно меняет в поведении
- **AND** указывается, как проверить, что фикс помог

#### Scenario: Причина вне кода

- **WHEN** причина лежит в конфигурации, данных или инфраструктуре
- **THEN** скилл прямо говорит об этом
- **AND** не предлагает правку кода, маскирующую симптом
